# 검사 차수 이월 요청문

새 차수의 01 초기 분석 직후 사용합니다. 이전 차수 자료가 없으면
건너뛰고 “이전 차수 비교 불가”로 기록합니다.

```text
이전 차수의 결과를 새 검출 목록과 대조해 주세요.

필요한 자료
- 사용자가 지정한 이전 차수 툴킷 또는 백업의 findings, progress, 개별 결과
- 새 차수의 data/findings.json과 현재 소스
이전 차수 경로가 없으면 AI가 사용자에게 그 경로를 묻습니다.

매칭 순서
1. sourceMapping.fingerprint 동일
2. 체커 코드 + 현재 파일 + 현재 함수 동일
3. 체커 코드 + 현재 파일 + 검출 코드 패턴 동일
매칭은 후보를 찾는 절차입니다. 다중 후보가 있으면 자동으로 하나를 고르지 않습니다.
동일한 지문으로 같은 항목임을 확인했을 때만 stableKey를 유지합니다.
2·3순위의 약한 매칭만으로 서로 다른 지문을 강제로 같은 키로 만들지 않습니다.

이월 판단
- 오탐·예외: 이전 workflowStatus=verified, verification.status=passed와
  실제 근거가 있는지 확인합니다. 코드·관련 호출 흐름·정책 범위·외부 규격·설정·
  예외 기한과 reviewTrigger가 현재에도 유효해야 결론을 재사용할 수 있습니다.
  그룹 대표 결론만 보지 않고 각 멤버의 안전 전제, 핵심 호출자·입력 타입·설정과
  잔존 동적 경로를 다시 확인합니다. 안전 조건이 제거되거나 범위가 넓어졌으면
  이전 오탐을 재사용하지 않습니다.
  하나라도 확인하지 못하면 needs-review로 두고 이전 결론은 참고로만 남깁니다.
  새 차수의 verified는 과거 상태를 복사하지 않고, prompts/03의 현재 소스
  스냅샷 → 실제 재검증 → 결과 기록 → seal-verification을 거쳐 부여합니다.
- 코드나 적용 조건이 바뀐 항목: needs-review. 변경 내용과 이전 판단을 기록합니다.
- 이전 fix가 다시 검출된 항목: 미반영 또는 회귀 가능성을 검토합니다.
  needs-review로 두고 이전 수정 내역과 현재 검출을 함께 남깁니다.
- operations: 운영 조치가 현재 유효한지 별도 확인합니다.
  확인 전에는 결론만 참고하고 analyzed 또는 needs-review로 둡니다.
- 매칭되지 않은 새 항목: 신규 검출로 둡니다.
- 이전에만 있는 항목: “이번 차수 미검출” 목록에 기록하고 새 findings에
  추가하지 않습니다. 검사 범위·규칙·실행 성공을 확인하지 않은 미검출을
  “수정 완료”나 “검증 완료”로 표현하지 않습니다.

기록과 확인
1. 이전 차수 경로·ID·매칭 규칙·코드와 정책 대조 근거를 reason/evidenceNote에 남깁니다.
   소스로 확인한 기술 사실과 사용자·운영 조직의 정책 승인 또는 위험 수용을
   별도 근거로 기록합니다.
2. 새 차수 결과와 progress를 갱신하되 이전 차수 원본은 바꾸지 않습니다.
3. 툴킷 디렉터리에서 다음을 실행해 정합성과 검증 연결을 확인합니다.
   python3 tools/sast_toolkit.py sync
   python3 tools/sast_toolkit.py validate
   python3 tools/sast_state.py status

보고
- 새 차수 건수, 규칙별 매칭 건수, 다중 후보·미확인 건수
- 결론 재사용 / 현재 재검증 완료 / 재검토 / 회귀 의심 / 신규 건수
- 이번 차수 미검출 ID와 검사 범위 확인 여부
- 다음에 확인할 코드·정책·운영 조건
```
