# Remediation Wave Prompt

```text
초기 분석과 확정된 프로젝트 정책을 기준으로 다음 SAST 조치 묶음을 진행해
주세요.

시작 전에 `sast-remediation-toolkit` 디렉터리에서
`python3 tools/sast_toolkit.py gate`를 실행합니다. 결과가
`GATE: READY`가 아니면 어떤 항목도 처리하지 않고 차단 사유를 보고합니다.

우선순위:
- 검증완료가 아닌 항목
- 높은 위험도 우선
- 같은 근본 원인을 함께 처리할 수 있는 그룹
- 동시에 작업할 경우 파일, 공통 유틸리티, 호출 관계와 테스트가 겹치지 않는 그룹

규칙:
1. 각 항목의 현재 소스와 PDF 검출 코드를 다시 대조합니다.
2. security-guides/<ID>.json을 먼저 작성합니다.
3. 체커 공통 가이드가 실제 코드에 맞는지 검토합니다.
4. 운영 소스의 기존 동작을 유지하는 최소 수정을 우선합니다.
5. 프로젝트 정책이 없는 중요한 결정은 임의로 정하지 말고 질문 하나를 남깁니다.
6. 수정 항목에는 위험과 영향 범위에 맞는 테스트를 추가하거나 실행합니다.
7. 각 항목의 security-results/<ID>.json을 작성합니다.
7-1. (선택) 프로젝트에 opengrep, semgrep, bandit, gosec 등 사용 가능한
   오픈소스 SAST 도구가 있으면, 변경한 파일에 한해 재검사를 실행해
   해당 검출이 사라졌는지 교차 확인하고 결과를 검증 근거에 기록합니다.
   도구가 없으면 이 단계는 건너뜁니다.
8. data/progress.json을 갱신합니다. 갱신은 작업 묶음이 끝날 때 1회만
   수행하고, 쓰기 직전에 최신 파일을 다시 읽어 다른 작업 묶음의 변경을
   덮어쓰지 않습니다.
9. tools/sast_toolkit.py sync와 validate를 실행합니다.

설정 및 운영 조치로 분류된 항목은 소스 변경 그룹과 분리합니다.

마지막 보고:
- 처리한 작업 그룹과 검출 ID
- 실제 변경 파일
- 수정/오탐/운영 설정/예외처리/추가 검토 결론
- 실행한 검증과 결과
- 중복으로 함께 해소된 항목
- 남은 위험과 다음 추천 그룹
```
