# Remediation Wave Prompt

```text
초기 분석과 확정된 프로젝트 정책을 기준으로 다음 SAST 조치 묶음을 진행해
주세요.

시작 전에 `sast-remediation-toolkit` 디렉터리에서
`python3 tools/sast_toolkit.py gate`를 실행합니다. 결과가
`GATE: READY`가 아니면 어떤 항목도 처리하지 않고 차단 사유를 보고합니다.

우선순위:
- 검증완료가 아닌 항목
- 높은 위험도 우선
- 같은 근본 원인을 함께 처리할 수 있는 그룹
- 동시에 작업할 경우 파일, 공통 유틸리티, 호출 관계와 테스트가 겹치지 않는 그룹

규칙:
1. 각 항목의 현재 소스와 PDF 검출 코드를 다시 대조합니다.
0-1. 연속 실행 모드: 사용자가 "연속으로", "N개 그룹", "끝까지" 등
   범위를 지정하면 웨이브 사이에 확인을 기다리지 않고 다음 그룹으로
   계속 진행합니다. 다음 경우에만 멈추고 보고합니다.
   - validate 에러가 발생해 자동 정리가 안 될 때
   - 프로필 constraints(변경 금지 영역)와 충돌하는 변경이 필요할 때
   - 공통 컴포넌트·외부 규격에 영향 주는 변경을 만났을 때
   - 파킹된 정책 질문이 5개 누적됐을 때 (아래 0-2)
   - 지정한 범위를 완료했을 때
   그 외 그룹 완료 시에는 한 줄 요약만 남기고 즉시 다음 그룹으로
   넘어갑니다.
0-2. 정책 질문 파킹: 웨이브 진행 중 코드로 판단할 수 없는 정책
   질문이 생기면 작업을 멈추지 않습니다. 해당 항목만 needs-review로
   두고 policyQuestions에 질문을 기록한 뒤 다음 항목으로 넘어갑니다.
   파킹된 질문은 연속 실행이 멈추는 시점에 모아서 제시하되, 같은
   정책에 걸린 항목들은 하나의 질문으로 병합하고
   SECURITY_GRILL_GUIDE.md 형식(추천 답변 포함)으로 하나씩 순서대로
   묻습니다. 답을 받으면 파킹됐던 항목들을 일괄 재처리합니다.
1-1. 모델 티어 위임 (sast-bulk-worker, sast-remediator 서브에이전트가
   있는 환경에서만): 판단이 필요 없는 대량 작업 — 멤버 경량 가이드
   생성, progress 집계, 증적 행 채우기, sync/validate 실행 — 은
   sast-bulk-worker에 위임하고, 가이드가 승인된 항목의 소스 수정은
   sast-remediator에 위임합니다. 결론 판정, 정책 해석, verified 승격,
   회귀 의심 분석은 위임하지 않고 메인 세션(현재 모델)이 직접
   수행합니다. 서브에이전트가 없거나 지정 모델을 쓸 수 없는 환경이면
   전 작업을 메인 세션이 수행합니다(기능 동일, 비용만 차이).
2. security-guides/<ID>.json을 먼저 작성합니다.
   동일 원인 그룹은 대표 항목 1개에 전체 가이드를 작성하고, 나머지
   멤버 항목은 groupGuideRef(대표 ID)와 summary·delta(대표와 다른
   점)만 담은 경량 가이드로 작성합니다. 차이가 실질적인 항목은 경량으로
   줄이지 말고 전체 가이드를 작성합니다.
   대상 항목 조회 시 findings.json 전체를 다시 읽지 말고 이번 작업
   그룹의 항목만 조회합니다.
3. 체커 공통 가이드가 실제 코드에 맞는지 검토합니다.
4. 운영 소스의 기존 동작을 유지하는 최소 수정을 우선합니다.
5. 프로젝트 정책이 없는 중요한 결정은 임의로 정하지 말고 질문 하나를 남깁니다.
6. 수정 항목에는 위험과 영향 범위에 맞는 테스트를 추가하거나 실행합니다.
7. 각 항목의 security-results/<ID>.json을 작성합니다.
6-1. 검증 시 사용한 수단을 result의 verification.method에 기록합니다.
   값은 프로필 validation.verificationMeans에 선언된 것 중에서
   사용합니다(build, lint, unit-test, scanner-recheck, manual-review 등).
   verified로 올리려면 method와 passed 결과가 함께 있어야 합니다.
7-1. (선택) 프로젝트에 opengrep, semgrep, bandit, gosec 등 사용 가능한
   오픈소스 SAST 도구가 있으면, 변경한 파일에 한해 재검사를 실행해
   해당 검출이 사라졌는지 교차 확인하고 결과를 검증 근거에 기록합니다.
   도구가 없으면 이 단계는 건너뜁니다.
8. data/progress.json을 갱신합니다. 갱신은 작업 묶음이 끝날 때 1회만
   수행하고, 쓰기 직전에 최신 파일을 다시 읽어 다른 작업 묶음의 변경을
   덮어쓰지 않습니다.
9. tools/sast_toolkit.py sync와 validate를 실행합니다.

설정 및 운영 조치로 분류된 항목은 소스 변경 그룹과 분리합니다.

마지막 보고:
- 처리한 작업 그룹과 검출 ID
- 실제 변경 파일
- 수정/오탐/운영 설정/예외처리/추가 검토 결론
- 실행한 검증과 결과
- 중복으로 함께 해소된 항목
- 남은 위험과 다음 추천 그룹
```
