# Project Security Policy Grill

## 목적

AI가 코드만으로 알 수 없는 프로젝트 정책을 한 번에 하나씩 확인하고, 답변을
프로젝트의 재사용 가능한 보안 정책으로 축적합니다. 질문 수를 늘리는 것이 목적이
아니라 같은 판단을 반복해서 묻지 않게 만드는 것이 목적입니다.

## 질문 전 규칙

질문하기 전에 반드시 다음을 수행합니다.

1. 검출 파일과 주변 코드를 읽습니다.
2. 호출부와 반환값 사용처를 확인합니다.
3. 관련 설정과 테스트를 확인합니다.
4. PDF의 체커 설명과 실제 검출 코드를 비교합니다.
5. 기존 `PROJECT_SECURITY_POLICY.md`와 `DECISION_LOG.md`를 검색합니다.

소스에서 답을 확인할 수 있으면 사용자에게 묻지 않고 근거를 기록합니다.

## 질문 방식

- 한 메시지에 질문 하나만 합니다.
- 질문의 대상 파일과 영향을 짧게 설명합니다.
- 추천 답변을 먼저 제시합니다.
- 선택에 따른 동작 차이와 위험을 설명합니다.
- 사용자가 선택하면 즉시 정책과 결정 로그에 기록합니다.
- 같은 범위의 후속 항목에는 확정 정책을 자동 적용합니다.

## 질문이 필요한 대표 조건

### Null과 빈 값

- null이 잘못된 요청인지, 값 없음인지, 기능 비활성화인지
- 빈 문자열과 null이 업무상 같은 의미인지
- 필수 데이터 누락 시 예외, 기본값, 미처리 중 무엇이 맞는지

추천 기본값: 필수 입력은 명시적 오류, 선택 입력만 안전한 기본값.

### 외부 프로토콜

- 해시, salt, 인코딩, 암호문 형식이 외부 명세에 고정되어 있는지
- 상대 시스템과 이전 데이터가 새 형식을 지원하는지
- 테스트 환경에서 호환성 검증이 가능한지

추천 기본값: 명세와 양쪽 사용처가 확인되기 전에는 형식을 변경하지 않음.

### 로그와 개인정보

- 운영상 반드시 남겨야 하는 필드가 무엇인지
- 마스킹, 부분 마스킹, 제거 중 어느 정책인지
- 보관 기간과 접근 통제가 있는지

추천 기본값: 인증정보와 비밀값은 제거 또는 전부 마스킹.

### 설정과 비밀값

- 런타임 주입 방식과 담당 환경
- 값이 없을 때 기동 실패와 기능 비활성화 중 어떤 정책인지
- profile별 기본값을 허용하는지

추천 기본값: 필수 비밀값 누락 시 명확히 기동 실패하고 안전하지 않은 기본값을
제공하지 않음.

### 예외와 Fallback

- 외부 연동 실패 시 전체 요청 실패, 부분 성공, 빈 응답 중 어떤 정책인지
- 기존 포괄 예외가 장애 격리 목적인지
- 재시도 또는 대체 데이터가 허용되는지

추천 기본값: 구체 예외를 먼저 처리하고 기존 최종 안전망은 의미를 보존.

### 동시성과 공유 상태

- 상태의 소유자가 요청, 세션, 애플리케이션 중 무엇인지
- 초기화 후 값이 변경되는지
- 여러 값을 하나의 불변조건으로 갱신하는지

추천 기본값: 요청 상태는 요청 범위에 두고, 초기화 상태는 불변으로 유지하며,
광범위한 직렬화는 피함.

### Mutable 객체

- 해당 객체가 내부 상태로 저장되는지 임시 계산에만 쓰이는지
- 요소까지 깊은 복사가 필요한지
- ORM 또는 프레임워크가 객체 정체성을 요구하는지

추천 기본값: 경계를 넘어 저장·반환되는 mutable 값만 필요한 깊이만큼 복사.

## 질문 형식

```text
정책 확인: <주제>

현재 확인된 사실:
- <소스와 리포트에서 확인한 내용>

결정이 필요한 이유:
- <코드만으로 판단할 수 없는 내용>

추천:
- <추천 답변과 이유>

질문:
<한 가지 결정만 질문>
```

## 결정 기록 형식

```text
결정 ID:
결정일:
주제:
적용 범위:
결정:
근거:
확인한 소스/명세:
영향받는 체커:
예외:
재검토 조건:
```

## Grill 종료 조건

- 높은 위험 항목의 판단을 막는 정책 공백이 없음
- 같은 질문을 다시 묻지 않아도 됨
- 외부 규격 및 운영 설정 항목의 담당 경계가 명확함
- 프로젝트 정책과 공통 기준의 차이가 기록됨
- 초기 작업 묶음의 순서와 제외 범위가 확정됨
