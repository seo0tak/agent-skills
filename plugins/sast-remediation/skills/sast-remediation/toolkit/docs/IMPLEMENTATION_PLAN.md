# Universal SAST Remediation Toolkit 구현 계획

**목표:** 현재 소스 트리, SAST PDF 1개, SAST 스프레드시트 1개를 관리되는
조치 워크플로우로 전환하는 프로젝트 중립 패키지를 만든다.

**아키텍처:** 대시보드 엔진과 정책 문서는 고정하고 프로젝트 프로필,
검출 목록, 체커 가이드, 항목별 가이드, 결과, 진행상태를 별도 데이터로
생성한다. JSON을 기준 기록으로, 생성된 JavaScript 미러를 로컬 HTML
직접 실행용으로 사용한다.

## 제약

- 고정 툴킷 파일에 원본 프로젝트의 조직, 보고서, 패키지, 체커 ID를
  포함하지 않는다.
- 프로그래밍 언어, 프레임워크, 빌드 도구를 가정하지 않는다.
- 현재 소스를 동작의 기준으로 사용한다.
- 대시보드는 로컬 서버 없이 동작한다.

## 작업

### 1. 워크플로우와 정책 문서

- 패키지 README와 빠른 시작 작성.
- 입력 준비 게이트(기계 점검 + 의미 대조), 초기화, 프로젝트 분석,
  보고서 정규화, 차수 이월, 정책 Grill, 조치, 검증, 증적 워크플로우
  정의.
- 범용 보안 정책 기준선과 테스트 가이드 정의.
- 각 워크플로우 단계의 재사용 프롬프트 제공 (00~06).

### 2. 표준 스키마와 예시

- 프로젝트 프로필, finding, 체커 가이드, 항목별 가이드, 결과, 진행상태
  스키마 정의. fingerprint는 소스 매핑 항목에서 필수.
- 실제 프로젝트 식별자가 없는 중립 예시 추가.
- JSON과 JavaScript 미러 규약 문서화.

### 3. 재사용 대시보드

- 프로젝트 중립 HTML 셸 작성.
- 검색, 필터, 집계, 추천, 상세 보기, 항목별 프롬프트 생성, 진행상태
  가져오기/내보내기, 결과 갱신 유지.
- 모든 프로젝트별 데이터를 `data/*.js`에서 로드.
- 워크플로우 상태 필터와 결론 필터의 독립 유지.
- 파일-브라우저 진행상태의 updatedAt 기반 병합과 충돌 배너.

### 4. 동기화와 검증 도구

- JSON 기록에서 JavaScript 미러와 결과 인덱스를 생성하는 표준
  라이브러리 도구 작성.
- preflight(파일 형식·개수·소스 존재)와 gate(기록 판정과 현재 입력
  재대조) 명령 작성.
- 필수 파일, 스키마, 중복 finding ID, enum 값, 보고서/소스 매핑 필드,
  미러 일관성, 스키마-검증기 enum 일치, progress-results 상태 일치,
  fingerprint 누락을 검사하는 검증기 작성.

### 5. 검증

- 모든 JSON 파일 검증.
- JavaScript 문법 검사.
- 대시보드의 필수 DOM 대상과 로컬 데이터 참조 검사.
- 고정 파일의 프로젝트 잔여 식별자와 금지 워크플로우 문구 스캔.
- 빈 데이터셋과 예시 데이터셋에 대해 패키지 검증기 실행.
