# 스킬 아키텍처 체크리스트

각 항목은 **적용 / 부분 / 미적용 / 해당없음**으로 판정한다. 해당없음은
스킬 성격상 불필요한 경우다(단순 변환형에 재개 절차는 해당없음).
괄호는 참조 구현(sast-remediation)에서의 예다.

## 1. 트리거 설계

- description이 "무엇을 한다 + 언제 발동한다"를 모두 담는가
- 영/한 병기 키워드로 두 언어 요청에 발동하는가
- 오발동 위험(범용 단어 단독 트리거)을 피했는가
- 발동 후 첫 행동이 명확한가 (파일 확인 → 없으면 요청하고 멈춤)

## 2. 입력 게이트

- 잘못된 입력으로 작업을 낭비하기 전에 시작 조건을 검사하는가
  (기계 점검 + 의미 대조 2단 게이트)
- 입력이 여러 형태면 모드를 자동 판정하고 모호하면 차단하는가
  (벤더/SARIF 모드, 세트 폴더)
- 승인 후 입력이 바뀌면 승인이 자동 무효되는가 (크기·경로 재대조)

## 3. 상태 설계와 기록

- 진행 상태가 대화가 아니라 파일에 남는가
- canonical 저장소가 하나로 정해져 있고 집계·미러와 구분되는가
  (results가 기준, progress는 집계)
- 작업 단위가 끝날 때마다 즉시 기록되는가 (항목별 JSON)
- 결정·판단에 사유가 필수로 붙는가 (reason/evidenceNote 필수)
- 작업 이력 로그가 있는가 (DECISION_LOG — 날짜 그룹, 최신 우선)

## 4. 중단 내성

- 전원·세션이 끊겨도 파일 상태로 재개되는가 (07-resume 절차)
- 재개 절차가 명문화되어 있는가 (무엇을 어떤 순서로 읽는지)
- 깨진(반쪽) 파일을 감지하고 파일명을 지목하는가
- 복구 규칙이 있는가 (항목만 재작성 / 집계는 canonical에서 재생성)
- 도구 자체 쓰기는 원자적인가 (임시 파일 + 교체)

## 5. 기계 강제 검증

- 규칙을 문서가 아니라 검증기가 지키게 하는가 (validate 명령)
- 검증기가 잡는 것: 정합성, enum, 필수 필드, 미러 드리프트, 스키마
  자기일치
- 제출·완료 직전의 strict 모드가 있는가
- 스킬 자체의 회귀 테스트 습관이 있는가 (문법 체크, 오류 주입,
  순수 함수 테스트)

## 6. 토큰·모델 최적화

- 대량 반복 작업과 판단 작업이 분리되어 있는가
- 반복 작업은 저비용 모델 서브에이전트로 위임 가능한가
  (agents/ 동봉, model: haiku/sonnet 고정, 판단·승격 금지 가드레일)
- 큰 데이터는 전체를 다시 읽지 않고 슬라이스로 조회하는가
- 동종 대량 항목에 대표+delta 패턴을 쓰는가 (그룹 대표 가이드)
- 동적 모델 탐지·벤치마킹을 하지 않는가 (역할 고정이 정답 — 탐지
  자체가 토큰 낭비)

## 7. 사람 개입(HITL) 설계

- 사람이 반드시 개입하는 지점이 최소이고 명시되어 있는가 (3곳:
  정책 답변, 초기 승인, 최종 확인)
- 연속 실행 모드가 있고 중단 조건이 열거되어 있는가
- 질문이 작업 전체를 세우지 않는가 (파킹 → 병합 제시 → 일괄 재처리)
- 사람 검토가 비동기로 가능한가 (대시보드 + 변경 흡수 절차)
- 질문할 때 추천 답변을 함께 제시하는가

## 8. 지식 산출물

- 지식 성격의 md 산출물에 OKF 호환 frontmatter가 있는가
  (type 필수, title/description/timestamp/tags 권장, 소프트 적용)
- index(목록)와 log(이력) 규약을 따르는가
- 상태 데이터(JSON)는 OKF 대상에서 제외했는가 (스키마 강제 필요)

## 9. 문서

- 절차 문서(USAGE)와 원리 문서(HOW_IT_WORKS)가 분리되어 있는가
- 사용자가 AI에게 "뭐라고 말해야 하는지" 예문이 있는가
- 치트시트·트러블슈팅이 있는가
- 스킬이 원리 질문을 받으면 원리 문서 기반으로 답하도록 지시했는가

## 10. 배포

- 플러그인 구조(plugin.json, skills/, agents/)를 갖췄는가
- 마켓플레이스에 등록되고 버전이 관리되는가
- 변경 시 버전을 올리고 사용자는 marketplace update로 받는가
- 스킬 없는 환경의 폴백이 있는가 (툴킷 단독 사용 경로)

## 판정 시 주의

- 파일에서 확인한 사실만 근거로 쓴다. "아마 있을 것"은 미적용이다.
- 스킬 성격에 맞지 않는 항목을 억지로 요구하지 않는다. 단순 변환형
  스킬의 정답은 대부분 "2·4·6·7 해당없음"이다.
- 개선 제안은 임팩트 순 3~5개로 제한한다. 전 항목 지적은 소음이다.
