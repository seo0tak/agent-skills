# skill-architect

이 저장소의 **스킬 설계 기준**을 제공하고 적용하는 메타 스킬입니다. 같은 기준으로
새 스킬을 설계하고, 기존 스킬을 점검하고, 원하면 개선 이력을 남깁니다. 문서·코드·실행
근거로 판단하고, 확인한 사항과 확인하지 못한 사항을 구분합니다.

## 작업 흐름

세 갈래 모두 같은 설계 기준(`ARCHITECTURE_CHECKLIST.md`)을 씁니다. 새 스킬은 설계를
마친 뒤 점검 절차로 한 번 확인합니다. 점검만 요청하면 보고로 끝나고, 수정은 사용자가
승인한 범위에서만 합니다.

```mermaid
flowchart TD
  req["요청"] --> kind{"무엇을 하려는가"}
  kind -- "새 스킬" --> d1["목적 · 입출력 · 부작용 확인"]
  d1 --> d2["설계 기준 범주를 설계 질문으로<br/>한 번에 최대 3개"]
  d2 --> d3["설계 요약"]
  d3 --> d4["스캐폴딩 · 평가<br/>skill-creator"]
  d4 --> c1
  kind -- "기존 스킬" --> c1["파일과 근거 읽기"]
  c1 --> c2["설계 기준 범주별 판정<br/>근거 수준 함께"]
  c2 --> c3["점검 보고와 개선 제안"]
  c3 --> c4{"사용자: 수정까지 승인?"}
  c4 -- "점검만" --> done["보고로 끝"]
  c4 -- "승인 범위" --> c5["변경 적용 · 검증"]
  kind -- "개선 이력" --> t1["개선 기록<br/>제안 → 평가 → 승인 → 적용 → 검증"]
  c5 -. "기록을 원하면" .-> t1
```

## 이렇게 요청합니다

- "새 스킬을 설계하려는데 기준에 맞춰 같이 봐줘"
- "이 스킬 점검해줘" / "sast-remediation 스킬 감사해줘"
- "지난 점검에서 승인한 개선을 적용하고 기록해줘" (개선 기록 사용)
