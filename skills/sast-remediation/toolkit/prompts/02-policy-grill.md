# 정책 확인 요청문

```text
초기 분석에서 발견한 정책 공백을 SECURITY_GRILL_GUIDE.md 방식으로
확정해 주세요.

전제: 프로젝트의 세부 동작이나 보안 용어를 모를 수 있습니다. 확인하지 못한
내용은 "모르겠다"로 남길 수 있게 하고, 제가 알고 있는 업무 사실을 중심으로
질문해 주세요.

규칙:
1. 질문 전에 관련 소스, 호출부, 설정, 테스트, 선택 보고서 가이드에 더해
   접근이 허용된 소스 밖의 증거(DB 스키마와 실제 데이터, 폼 required, profile 설정,
   API 문서, 운영 로그)를 확인합니다.
2. 소스나 자료로 확인한 사실과 근거를 먼저 알려 드립니다. 사용자가 다른
   사실이나 빠진 조건을 알고 있다면 정정할 수 있음을 안내합니다. 선택에
   따라 코드 변경이 달라지지 않는 내용은 묻지 않습니다.
3. 한 번에 질문 하나만 합니다.
4. 보안 용어가 아니라 업무 사실로 묻습니다. 선택지는 실제 동작의 차이,
   전제한 업무 조건이 다를 때의 영향, 되돌리기 난이도로 설명하고
   "모르겠다"를 항상 포함합니다. 현재 사용자가 확인하기 어려운 질문에는
   확인할 담당 역할을 표시합니다.
5. 내가 모르겠다고 하면 동작 보존안의 잔여 위험과 관찰 방법·영향을 설명합니다.
   그 방법을 선택했고 변경이 승인 범위에 있을 때만 baseline-default로
   기록합니다. 답변이나 권한이 없으면 deferred로 두고 재개 조건을 남깁니다.
6. 내 답변을 project/PROJECT_SECURITY_POLICY.md에 반영하고, 결정은
   data/decisions.json에 항목으로 추가한 뒤 sync를 실행합니다
   (DECISION_LOG.md는 거기서 생성됨). decidedBy는 user /
   baseline-default / choice-irrelevant / deferred 중 하나이며,
   baseline-default에는 observation과 reviewTrigger가 없으면 validate가
   오류를 냅니다. 관찰의 실제 수행이나 사용자 승인까지 인증하지는 않습니다.
   소스·프레임워크 계약으로 확인한 기술 사실과 정책 승인·위험 수용을 같은
   결정으로 합치지 않습니다.
7. 확정된 정책이 적용되는 모든 검출 ID와 작업 그룹을 갱신합니다.
8. 적용 범위·기한·새 증거·재검토 조건을 확인합니다. 유효한 같은 정책은 재질문하지 않습니다.
9. 마지막에는 보류된 질문을 확인할 담당 역할별로 묶어 정리합니다.

높음 이상 항목의 조치를 막는 정책부터 질문해 주세요.
```
