# 공통 보안 판단 기준

## 적용 원칙

이 문서는 모든 프로젝트의 기본 판단 기준입니다. 프로젝트의 실제 코드,
외부 규격, 저장 데이터 호환성 또는 승인된 운영 정책과 충돌하면 해당 프로젝트
정책이 우선합니다. 예외는 근거와 범위를 기록해야 합니다.

이 문서의 추천 기본값은 **정책이 확인됐을 때**의 기준입니다. 답하는
사람이 모르거나 증거가 없어 미확인으로 적용할 때는 보안적으로 최선인
쪽이 아니라 **현재 운영 동작을 보존하고 되돌리기 쉬운 쪽**을 택하고,
승인된 관찰 방법과 확인 가능한 재검토 조건을 붙입니다.
사용자 선택·변경 권한이 없으면 보류합니다. 동작 보존 역시 위험이 남을 수 있으므로
고위험 항목은 필요한 추가 결정과 대응을 보고합니다. 모르는 사람이 안전한
기본값을 대량 승인하면 운영이 깨지기 때문입니다. 조건별 미확인 기본값은
`SECURITY_GRILL_GUIDE.md`에 있습니다.

## 판단 근거 분리

항목별 기록에서 다음 근거를 구분합니다.

- `report`: 선택 보고서(PDF·스프레드시트 또는 SARIF)가 제공한 사실
- `source`: 현재 소스와 호출 관계에서 확인한 사실
- `project-policy`: 사용자와 운영 조직이 확정한 정책
- `baseline`: 이 문서의 일반 보안 원칙
- `inference`: 위 자료로부터 도출한 해석

추론을 사실처럼 기록하지 않습니다.

## 최소 변경

- 운영 동작과 외부 계약을 유지하는 가장 작은 변경을 우선합니다.
- 스캐너 통과만을 위한 의미 없는 코드 변경은 피합니다.
- 같은 근본 원인을 해결하는 중복 검출은 한 번에 처리할 수 있습니다.
- 공통 함수 변경은 호출부와 데이터 호환성을 확인한 뒤 수행합니다.

## Null 처리

- null 가능 값은 역참조 직전에 출처와 의미를 확인합니다.
- 필수 입력은 명확한 검증 오류 또는 도메인 예외로 처리합니다.
- 선택 입력은 업무 의미에 맞는 기본값 또는 값 없음으로 표현합니다.
- null을 빈 문자열, 빈 목록 또는 0으로 바꾸기 전에 의미가 같은지 확인합니다.
- public API와 내부 helper의 null 정책을 구분하되 호출 흐름 전체에서 일관성을
  유지합니다.
- 표준 라이브러리의 null 가능성은 실제 API 계약을 확인합니다.

## 입력 검증

- 외부 입력이 신뢰 경계를 통과하는 지점에서 검증합니다.
- DTO 전체 제약은 하나의 검증 흐름으로 모으고 교차 필드 규칙을 분리합니다.
- 길이, 범위, 형식, 허용값과 필수 여부를 검증합니다.
- 서비스가 다른 내부 경로에서도 직접 호출될 수 있다면 핵심 불변조건을 서비스
  경계에서도 보장합니다.
- 필드마다 의미 없는 wrapper 메서드를 만드는 방식은 피합니다.

## 예외 처리

- 구체적으로 복구하거나 변환할 수 있는 예외를 먼저 처리합니다.
- 기존의 최종 포괄 예외가 장애 격리 안전망이면 마지막에 유지합니다.
- catch 내부의 즉시 반환이 스캐너 대상이면 결과 변수를 사용하되 기존 fallback
  의미를 보존합니다.
- 예외를 빈 값으로 삼키지 않습니다.
- 로그에는 필요한 문맥만 남기고 비밀값과 개인정보를 포함하지 않습니다.
- 생성자 검증 또는 초기화 실패를 무조건 숨기지 않습니다.

## Mutable 데이터

- 배열, 목록, 맵, 날짜 및 mutable 객체를 장기 상태로 저장하거나 반환할 때
  방어적 복사를 검토합니다.
- String, 숫자 wrapper, enum 등 immutable 값의 단순 할당은 방어적 복사 대상이
  아닙니다.
- stream 사용 자체는 복사를 보장하지 않습니다. mutable 요소가 그대로 전달되는지
  확인합니다.
- 로컬 계산에서 scalar 값만 추출하고 원본을 변경하지 않는 경우 직접 사용과
  보안 효과가 같을 수 있습니다.
- Entity 및 ORM 컬렉션을 복사하면 영속성 추적이 달라질 수 있으므로 저장·조회
  흐름을 확인합니다.

## 숫자와 경계값

- 음수 검사만으로 정수 오버플로를 막을 수 없습니다.
- 덧셈, 곱셈, 캐스팅 및 메모리 크기 계산은 연산 전 범위를 확인하거나 정확한
  연산 API를 사용합니다.
- 배열과 버퍼 크기는 음수, 최대값, 계산 오버플로를 함께 검증합니다.
- narrowing cast는 허용 범위와 잘림 의도를 확인합니다.

## 분기와 반복

- switch case가 return 또는 throw로 종료되면 break가 필요하지 않습니다.
- 의도된 fall-through는 같은 처리 그룹임을 코드와 주석으로 명확히 합니다.
- 단순 반복문 인덱스의 final 여부보다 외부 캡처와 공유 상태 변경을 확인합니다.
- 변경이 없는 품질 패턴을 보안 취약점으로 과장하지 않습니다.

## 암호와 해시

- 표준 암호 알고리즘의 비트 연산과 키 스케줄을 일반 코드 규칙으로 변경하지
  않습니다.
- 알고리즘 변경 전 공식 규격과 known-answer test를 확보합니다.
- 비밀번호 저장, 무결성 검증, 외부 프로토콜, 식별자 익명화의 해시 요구사항을
  구분합니다.
- salt 또는 인코딩을 추가하면 저장값, 조회값, 외부 규격과 호환되는지 모든 사용처를
  확인합니다.
- 고정 키와 비밀값은 배포 환경의 안전한 주입 방식으로 관리합니다.

## 외부 연동과 저장 형식

- 외부 기관이 지정한 인코딩, 암호화, 해시, 서명, 필드 길이 및 문자셋을 임의로
  변경하지 않습니다.
- 생성과 조회, 저장과 복원, 송신과 검증 양쪽 코드를 모두 확인합니다.
- 기존 데이터 마이그레이션 없이 형식을 변경하지 않습니다.
- 소스 조치가 부적절하면 규격 근거를 포함해 예외처리로 분류합니다.

## 인증, 세션 및 공유 상태

- 요청별 데이터가 static 또는 singleton mutable 상태에 남지 않도록 합니다.
- 초기화 후 불변인 상태와 요청 중 변경되는 공유 상태를 구분합니다.
- 동시성 문제를 무조건 광범위한 synchronized로 해결하지 않습니다.
- atomic 연산, 불변 객체, 요청 범위 상태, 동시성 컬렉션 또는 좁은 lock 중 실제
  불변조건에 맞는 방식을 선택합니다.
- ThreadLocal 및 MDC는 요청 종료 시 정리 경로를 확인합니다.

## 로깅과 개인정보

- Authorization, Cookie, token, password, secret 및 개인식별정보를 원문으로
  기록하지 않습니다.
- 민감 헤더 이름은 대소문자와 변형을 고려해 마스킹합니다.
- 디버그 출력, 임시 alert, 콘솔 출력, 테스트 URL과 자격정보 주석을 제거합니다.
- 장애 분석에 필요한 오류 정보는 안전한 구조화 로그로 남깁니다.

## 직렬화와 DTO

- 실제 Java/native serialization과 JSON 직렬화를 구분합니다.
- Serializable이 필요하면 버전과 민감 필드 처리 정책을 확인합니다.
- 세션 저장 또는 분산 캐시 사용 여부를 확인한 뒤 인터페이스 제거를 결정합니다.
- DTO의 getter 반환값이 mutable이면 내부 상태 노출 여부를 확인합니다.

## 설정과 비밀값

- 설정 파일에서 발견된 문제와 소스 문제를 분리합니다.
- 비밀값은 환경 변수, 비밀 저장소 또는 승인된 런타임 주입 방식으로 관리합니다.
- 빈 비밀번호가 실제 무인증 정책인지 단순 누락인지 확인합니다.
- 운영 설정이 필요한 항목에는 필요한 키, 환경, 담당자, 배포 확인 방법을 기록합니다.
- 기본값 추가가 보안을 약화시키지 않는지 확인합니다.

## 오탐 기준

오탐은 단순히 수정하기 어렵다는 의미가 아닙니다. 다음을 증명할 수 있어야 합니다.

- 검출된 데이터가 실제로 위험한 타입 또는 값이 아님
- 위험한 사용처로 흐르지 않음
- 프레임워크 또는 언어 계약이 안전성을 보장함
- 표준 알고리즘이나 외부 규격이 요구하는 의도된 코드임
- 검출 코드가 현재 소스에 존재하지 않으며 버전 불일치가 해소됨

오탐 의견에는 파일, 함수, 검출 코드, 실제 타입 또는 호출 흐름을 포함합니다.

## 예외처리 기준

예외처리는 취약 가능성을 인정하지만 즉시 소스 변경이 부적절한 경우입니다.

- 외부 규격과 호환성을 깨뜨림
- 기존 저장 데이터 전체 마이그레이션이 필요함
- 프레임워크 필수 구조임
- 운영 승인과 배포 변경이 선행되어야 함

보완 통제, 적용 범위, 재검토 조건과 담당 주체를 함께 기록합니다.
