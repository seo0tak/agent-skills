전체 흐름 1. 준비와 첫 요청 2. 입력 확인과 초기 분석 — 00, 01 3. 이전 차수와 정책 — 06, 02 4. 조치와 검증 — 03 5. 대시보드 검토와 백업 6. 중단한 작업 재개 — 07 7. 결과 대조와 제출 — 04, 05 명령어 요약

사용 가이드

이 페이지는 USAGE.md에서 생성한 읽기용 가이드입니다.

받은 SAST 검출 결과를 현재 소스와 대조하고, 조치·검증·증적까지 관리하는 가이드입니다. 처음에는 1번부터, 중단한 작업은 6번부터 확인하세요. 사용자 요청이 없을 때 스스로 실행하거나 배포하는 도구는 아닙니다.

전체 흐름

준비 → 00 입력 확인 → 01 초기 분석
                       ↓
            06 이전 차수 대조 (자료가 있을 때)
                       ↓
            03 조치·검증 반복 ← 02 정책 질문 (수시)
                       ↓
            04 대시보드 변경 대조 → 05 증적 생성·검토

프롬프트 번호는 파일 이름입니다. 작업 순서는 위 흐름을 따르며, 세션이 끊기면 07 재개 절차로 현재 기록부터 확인합니다.

1. 준비와 첫 요청

프로젝트 루트에 툴킷 전체를 sast-remediation-toolkit/ 이름으로 복사하고, input/에 이번 차수 자료를 넣습니다.

  • 벤더 보고서: 상세 PDF 1개 이상 + 검출 목록 스프레드시트 1개

  • SARIF: 표준 .sarif 파일 1개. PDF는 선택 자료입니다.

여러 차수·도구의 자료는 input/<세트명>/으로 분리합니다. 한 차수에는 한 세트만 사용합니다. 여러 세트가 있으면 사용할 세트를 지정하세요.

이 스킬을 설치했고 프로젝트 파일을 읽을 수 있는 AI 도구에서는 “SAST 결과 조치해줘”라고 요청해도 됩니다. Claude Code·Codex 등 환경별 설치 방법은 저장소 README를 따릅니다. 설치본 갱신은 기존 프로젝트 복사본을 바꾸지 않습니다. 업그레이드는 새 설치본의 docs/VERSIONING.md에 따라 별도로 진행합니다.

프로젝트 파일을 읽을 수 있는 AI 도구에는 다음처럼 요청합니다.

sast-remediation-toolkit/prompts/00-preflight.md를 읽고 수행해줘.

파일을 읽거나 수정할 수 없는 일반 채팅에서는 해당 프롬프트의 요청문과 필요한 자료를 전달해야 합니다. AI가 로컬 파일을 수정했다고 가정하지 마세요.

2. 입력 확인과 초기 분석 — 00, 01

AI는 먼저 입력 개수·실제 파일 형식·소스 존재를 검사하고, 전체 입력의 경로·크기·SHA-256을 기록합니다. 그다음 프로젝트 식별정보, 검사 차수, 검출 건수와 소스 범위를 실제 내용으로 대조합니다.

  • GATE: READY: 초기 분석을 진행할 수 있습니다. 소스 변경 승인은 별도입니다.

  • BLOCKED: 차단 사유에 맞게 입력을 보완합니다. 임의로 승인 값을 바꾸지 않습니다.

  • 승인 후 입력을 바꾸거나 옛 승인에 해시가 없으면 00부터 다시 대조합니다.

초기 분석 후에는 다음을 확인하세요.

산출물확인할 내용
project/PROJECT_ANALYSIS.md모듈·빌드·테스트 방법·변경 제한
data/findings.json선택 보고서의 검출 목록과 건수
SECURITY_CHECKLIST.html매핑 상태, 위험도, 작업 그룹과 미확인 항목

“미확인”은 0건이나 문제가 없다는 뜻이 아닙니다. 소스에 매핑한 항목의 fingerprint는 차수 간 대조용 지문이며, 그 자체가 오탐·수정 완료의 증거는 아닙니다.

3. 이전 차수와 정책 — 06, 02

이전 차수 자료가 있으면 그 툴킷 또는 백업 경로를 알려주세요.

prompts/06-carry-over.md를 수행해줘. 이전 차수는 ../sast-previous/에 있어.

이전 오탐·예외는 검증 근거와 현재 코드·정책·외부 규격의 유효성을 확인한 뒤 결론을 재사용합니다. 새 차수의 검증 완료는 현재 소스에서 다시 확인합니다. 이전에만 있던 항목은 “이번 차수 미검출”이며, 검사 범위를 확인하지 않고 “해소”로 단정하지 않습니다.

AI는 자료로 확인할 수 없는 업무 사실만 한 번에 하나씩 묻습니다. 선택지에는 동작 차이와 위험이 포함되며 “모르겠다”도 가능합니다. 미확인 기본안에 관찰 로그 등의 변경이 필요하면 그 방법과 영향까지 승인된 범위에서 적용합니다. 답변이나 권한이 없으면 해당 항목을 보류합니다.

결정 정본은 data/decisions.json입니다. project/DECISION_LOG.md는 sync가 만드는 읽기용 기록입니다. 같은 범위의 유효한 정책은 재사용하지만, 기한이나 새 증거가 생기면 다시 확인합니다.

4. 조치와 검증 — 03

초기 분석을 검토한 뒤 처리 범위를 요청하세요.

작업 그룹은 grouping.workGroup으로 묶은 분류 단위입니다. 조치 실행은 이번 요청에서 처리하도록 승인된 범위이며 하나 이상의 작업 그룹을 포함할 수 있습니다.

prompts/03-remediation-wave.md에 따라 WG-003을 처리해줘.
승인한 범위에서 그룹 3개를 연속 처리해줘. 정책 질문은 해당 항목을 보류하고 모아서 알려줘.

AI는 수정 직전과 직후에 체크포인트를 저장하고, 검증 직전에 소스 스냅샷을 저장합니다. 검증을 실제 실행한 뒤 그 결과를 소스와 연결합니다. 스냅샷을 만드는 것과 테스트가 통과하는 것은 별개의 일입니다.

연속 실행도 승인 범위 안에서만 이어집니다. 추가 권한, 공통 컴포넌트· 외부 규격 영향, 해결되지 않는 오류, 안전한 저장 불가 또는 사용자 중단 요청이 있으면 멈춥니다. 정책 질문이 있는 항목만 보류하고 독립 작업은 계속할 수 있습니다.

중요 변경·공통 코드·오탐·예외는 근거를 직접 검토하세요. 일부 항목만 표본으로 검토했다면 확인한 ID와 선정 기준을 기록하세요. 표본 검토는 나머지 항목의 안전성을 보장하지 않습니다.

5. 대시보드 검토와 백업

SECURITY_CHECKLIST.html은 별도 서버 없이 여는 화면입니다. 브라우저 정책에 따라 로컬 파일이나 저장소 접근이 제한될 수 있습니다.

버튼역할
파일 결과 다시 읽기sync로 생성한 파일 결과를 다시 읽기; sync 자체를 실행하지 않음
답변에서 결과 추출“AI 답변에서 브라우저 초안 만들기” 영역에서 정해진 응답 라벨을 읽어 초안으로 저장
현재 결과 JSON 내보내기현재 항목의 결과를 파일로 내려받기
상태+결과 백업진행상태·비고와 상세 결과 초안을 함께 내려받기
상태+결과 불러오기같은 작업공간의 유효한 백업을 항목별로 병합; 더 최신인 현재 값은 유지
읽지 못한 저장본 백업읽기에 실패한 원본이 있을 때만 표시; 그 원문을 보존용으로 내려받기
필터 초기화검색·필터를 초기화

진행상태별 “분석 완료”, “변경 완료”, “검증 완료” 건수는 서로 누적하지 않고 각각의 현재 상태만 셉니다. “검증 완료 상태 비율”은 전체 검출 항목 중 현재 상태가 verified인 항목의 비율입니다. 검색·위험도·체커·언어 필터로 검토 범위를 줄일 수 있습니다. 작업 그룹은 화면 필터가 아니라 grouping.workGroup 분류와 query --group <WG>로 확인합니다.

JSON 정본이나 항목별 결과를 바꾼 뒤에는 sync로 JS 미러와 결과 인덱스를 먼저 갱신하세요. 그런 다음 파일 결과 다시 읽기로 생성된 인덱스를 다시 읽습니다. 이 버튼만 눌러서는 JSON 변경이 화면에 반영되지 않습니다.

브라우저 저장과 파일 저장은 다릅니다

  • “브라우저 초안: 저장됨”: 이 브라우저에 상세 결과를 임시 보관했습니다.

  • “브라우저 초안: 현재 화면에만 있음 · 저장 실패”: 아직 저장하지 못했습니다. 화면을 닫기 전에 백업하세요.

  • “정본 대조: 반영 대기”: 아직 파일 결과와 일치하지 않습니다.

  • “정본 대조: 내용 일치”: 읽어 온 파일 결과와 초안 내용이 같습니다. 실제 테스트의 적절성은 별도로 확인해야 합니다.

  • “정본 대조: 정본이 더 최신”: 파일에서 읽은 결과가 브라우저 초안보다 최신입니다. 두 기록을 대조한 뒤 필요한 내용을 반영하세요.

다운로드는 정본 반영의 증거가 아닙니다. 백업을 AI에게 전달해 04 절차로 출처와 근거를 대조하고, 확인한 결과만 파일에 반영한 뒤 sync하세요.

브라우저 데이터는 저장소 삭제·시크릿 모드·용량 제한 등으로 사라질 수 있습니다. 저장 오류가 표시되면 닫기 전에 백업을 내려받으세요. 읽지 못한 저장본은 자동 덮어쓰기를 막습니다. 복구나 불러오기를 시작하기 전에 먼저 [읽지 못한 저장본 백업]으로 원문을 내려받고, 실제 파일이 생성되어 열리는지 사용자가 확인하세요. 화면에 성공 메시지가 보여도 다운로드 성공을 도구가 보장하지는 않습니다. 현재 화면의 새 작업도 [상태+결과 백업]으로 따로 내려받고 실제 파일을 확인합니다. 두 원본을 보존한 다음 04에서 복구를 요청하거나 [상태+결과 불러오기]로 유효한 백업을 직접 불러옵니다. 일반적인 불러오기는 항목별 updatedAt을 비교해 병합하고 더 최신인 현재 값을 유지합니다. 읽지 못한 저장본을 보호 중이었다면 성공한 불러오기가 그 보호 대상 브라우저 저장 항목을 검사·병합한 내용으로 교체합니다. 다른 작업공간이나 식별자가 없는 옛 백업은 원본을 보존하고 04에서 출처를 확인합니다. 검출 ID만 같다고 합치지 않습니다.

6. 중단한 작업 재개 — 07

prompts/07-resume.md로 상태를 확인하고, 이전에 승인한 WG-003 범위에서 이어서 해줘.

재개 시에는 게이트와 원본 상태를 먼저 검사합니다. 손상된 진행상태를 조회하거나 오래된 인덱스로 완료율부터 계산하지 않습니다.

  • 복구는 먼저 미리보기로 확인하고 --apply를 붙일 때만 반영합니다.

  • 결과·체크포인트·백업에 없는 임시 메모는 복구할 수 없습니다.

  • 중간 수정은 현재 diff와 대조해 같은 패치를 중복 적용하지 않습니다.

  • stale: 검증과 연결한 소스 또는 근거가 바뀌었습니다.

  • unbound: 옛 검증에 소스 연결이 없습니다. 현재 소스에서 재검증해야 합니다.

  • fresh: 지정한 파일과 저장된 검증 근거가 일치합니다. 외부 시스템·DB·정책의 유효성까지 보장하지는 않습니다.

자동 재시작·네트워크 재연결·정책 로그 감시는 제공하지 않습니다. 세션을 다시 열어 요청하면 마지막으로 온전히 저장된 기록부터 확인합니다.

7. 결과 대조와 제출 — 04, 05

prompts/04-reconcile-results.md는 브라우저 검토 내용을 정본에 반영합니다. prompts/05-final-evidence.md는 templates/evidence-columns.md에 따라 제출용 xlsx 4종을 만듭니다. 파일명은 프로필의 evidence.outputs에서 정합니다.

제출 전에는 다음을 함께 확인하세요.

  1. validate --strict의 오류와 경고

  2. sast_state.py status의 중간 작업·오래된 검증·연결 없는 검증

  3. 실제 테스트 결과, 미검증·예외·운영 조치의 표시

  4. 제출 파일의 수치·근거·표현과 사용자 검토

자동 검사 OK는 데이터 검사 통과입니다. 취약점 해소나 제출 승인을 대신하지 않습니다. 미검증 항목이 있으면 미검증 목록에 명확히 남깁니다.

명령어 요약

툴킷 디렉터리에서 실행합니다. Python 도구는 표준 라이브러리만 사용합니다. <ID>, <WG>, <파일>은 실제 값으로 바꾸세요.

명령용도
python3 tools/sast_toolkit.py preflight입력 기계 점검
python3 tools/sast_toolkit.py gate입력 승인과 현재 파일 대조
python3 tools/sast_toolkit.py sync정본에서 미러·인덱스·가이드 HTML 생성
python3 tools/sast_toolkit.py validate --strict제출 전 데이터 검사
python3 tools/sast_toolkit.py query --summary파일을 도구로 읽어 상태별 현황 집계
python3 tools/sast_toolkit.py query --group <WG>해당 그룹의 모든 진행상태 조회
python3 tools/sast_state.py status재개 후보·체크포인트·검증 신선도 확인
python3 tools/sast_state.py recover-progress --backup <파일>복구 미리보기; 실제 반영은 --apply 추가

체크포인트·검증 연결 예시는 prompts/03-remediation-wave.md, 전체 명령과 종료 코드는 tools/README.md를 참고하세요. 동작 원리·저장 한계는 docs/HOW_IT_WORKS.md에 정리했습니다.
