# 작업 이력·운영 기록·진단 상세 분리 검토

## 범위와 기준

사용자가 승인한 기본 작업 이력, 고급 시스템 운영 기록, 펼쳐 보는 진단 상세를
반영한다. 시작점은 `6c2b08f`, 작업 브랜치는 `codex/activity-audience-views`다.
기존 정책상 산출물 형식 변경 없는 대시보드 개선이므로 SAST 1.14.1로 배포하고
Architect 0.4.3은 유지한다. 설치본·프로젝트 툴킷·고객 자료는 변경하지 않는다.

원본 이벤트의 schemaVersion·필드·ID·내용과 보관 정책은 그대로다. 화면의 분류·
작업 묶기만 추가하며, 별도 디버그 수집·외부 전송·자동 삭제는 추가하지 않는다.
이 구분은 권한별 접근 통제가 아니다. 파일을 열 수 있는 사람은 고급 기록도 볼 수 있다.

## 개선 전 확인

- Node 110개와 Python 134개 기준 테스트가 통과했다.
- 기존 화면은 출처·결과·중요 표시로 필터링하며 사용자 작업과 내부 처리를
  같은 목록과 원시 전후 데이터로 보여줬다. 용도별 구분은 없었다.
- 합성 이벤트 75개를 실제 Chromium에서 불러왔을 때 전체 기록이 집계되고,
  별도 시스템 운영 기록 화면은 없었다. 고객 실행 자료로 일반화하지 않는다.
- 별도 문서 조회 시험에서 실제 조치만 보는 방법, 내부 기록 분리, 진단 화면의
  진입 경로를 찾을 수 없었다. 갱신 후 동일 질문에서는 작업 이력 → 필요할 때
  시스템 운영 기록·진단 상세로 안내했고 보존·추가 수집의 한계를 구분했다.

## 확인할 불변 조건

- 화면 상태 변경과 실제 소스 수정, 명령 성공과 취약점 검증 완료를 구분한다.
- 기록으로 확인할 수 있는 전후 변화만 표시하고, 관측 시각을 실제 수정 시각으로
  바꾸지 않는다. 누락·축약·분류 미확인은 임의의 정상·완료로 해석하지 않는다.
- 같은 논리 작업의 시작·종료·재시도는 연결하되 다른 차수·항목·작업은 섞지 않는다.
  과거 실패가 최신 시도의 실제 결과를 덮지 않으며 종료 미확인은 보존한다.
- 정상 내부 처리는 기본 화면에서 줄이고, 확인이 필요한 실패·중단은 사용자에게
  영향과 다음 확인 사항을 알린다. 원본은 진단 상세에서 조회할 수 있다.
- 필터·페이지·펼치기는 저장값이나 로그를 변경하지 않는다. 브라우저 백업과
  파일 이력의 출처를 유지한다. 페이지·내부 스크롤·키보드·좁은 화면을 확인한다.

## 구현·배포 검증

- 기본 작업 이력, 접힌 시스템 운영 기록, 행별 진단 상세와 항목별 동일 구조를
  구현했다. 원본 저장·백업·스키마·명령에는 변경이 없다.
- 독립 리뷰에서 실제 명령 이름의 분류 누락, 시작·종료의 편측 스냅샷을 변화로
  잘못 표시하는 문제, 오래된 시도 종료가 새 미종료 시도를 가리는 문제를 수정했다.
  서로 다른 필드의 편측 스냅샷도 시작 시·종료 시 관측으로 표시한다.
- 정본 변경은 중요 표시만이 아니라 기록된 내용으로 분류한다. 기준 관측·해시·
  시각만 바뀐 내부 기록은 시스템으로, 의미를 모르는 변경은 분류 미확인으로 남긴다.
  사용자 제목·위험도·단순 변경의 문구도 정리했다. 독립 재검토 결과 READY다.
- 최종 정본 테스트 288개(SAST Python 134, Node 129, Architect 24, 패키징 1),
  배포 사본 263개(Python 134, Node 129)가 통과했다. 각 회귀의 실패 재현 후
  통과를 확인했으며, 독립 검토자는 초점 회귀 6개와 최종 편측 회귀 2개를 확인했다.
- JavaScript 구문 검사, 정본·사본 일치, 버전 정합성, 변경 공백 검사를 통과했다.
  validate는 미초기화 배포물의 입력 없음 경고 1건만 반환했다. 배포 디렉터리에
  실제 `data/activity/` 기록이 생성되지 않은 것도 확인했다.
- 최종 합성 파일 이벤트 95개를 실제 Chromium에서 조회했다. 사용자 작업 73개는
  50/23개로 나뉘고 시스템 10개(분류 미확인 1개)는 기본적으로 접혀 있었다.
  실패 필터 8개·종료 미확인 2개, 재시도 묶기·서로 다른 필드의 관측 표시를 확인했다.
- 1440px·390px 화면에 가로 넘침이 없고, 긴 목록은 내부 스크롤됐다. 키보드로
  진단 상세를 열고 닫았으며 PageDown으로 목록 안에서 이동했다. 시스템 필터가
  작업 목록을 바꾸지 않았고, 항목 상세는 현재 차수 작업 71개만 조회했다.
- 필터·페이지·펼치기를 조작해도 파일 이벤트와 브라우저 저장값은 바뀌지 않았다.
  합성 메모를 실제 저장한 뒤 새로고침·검색으로 전후 내용과 브라우저 저장 출처를
  확인했다. HTML 모양의 문자열도 요소로 실행되지 않고 텍스트로 표시됐다.
- README·사용 안내·설계 설명·버전 정책과 배포 사본을 갱신했다. main 통합·푸시는
  승인된 후속 단계이며 실제 원격 상태는 Git 기록으로 확인한다.

## 검토 방법과 한계

호출 가능한 LSP가 없어 범위를 좁힌 소스·텍스트 탐색과 실행 검사를 사용한다.
실제 고객 차수, Windows 실기기, 설치본 갱신은 범위 밖이다. 화면은 실시간
감시기가 아니고, 진단 상세는 이미 저장된 정보만 보여준다. 누적 기록기의 기존
저장·중단 한계는 `skills/sast-remediation/toolkit/docs/ACTIVITY_LOG.md`를 따른다.
