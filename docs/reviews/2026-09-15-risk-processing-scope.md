# 위험도 처리 범위 — 구현·검토 기록

## 범위

사용자가 승인한 설계에 따라 SAST 5단계 위험도 중 최소 처리 등급을 선택하고,
그 이상만 상세 분석·조치·검증하도록 구현했다. 전체 보고서와 범위 밖 기존
상태는 보존한다. 고객 소스·프로젝트 복사본·설치본은 변경하지 않았다.

- SAST 배포 파일: **1.13.0**. Architect: **0.4.3**, 기능 변경 없음.
- 작업 시작점: `98f50d5`. 작업 브랜치: `codex/risk-processing-scope`.
- 설계: [위험도 처리 범위 설계](../superpowers/specs/2026-09-15-risk-processing-scope-design.md).
- 사용 계약: [PROCESSING_SCOPE.md](../../skills/sast-remediation/toolkit/docs/PROCESSING_SCOPE.md).

## 주요 변경

- profile의 선택 필드 `processingScope`에 작업공간·차수·최소 등급·기록자·
  시각·사유를 저장한다. 현재 입력 승인과 파일 manifest를 재확인한다.
- `scope`로 읽기·설정하고 `query --scope in-scope`로 상세 대상을 조회한다.
  등급 순서는 고정된 5단계를 사용하며 숫자 rank가 범위를 바꾸지 않는다.
- before-edit, snapshot, seal-verification에서 대상 여부를 다시 확인한다.
  after-edit와 복구는 범위 밖에 이미 생긴 작업도 보존한다.
- HTML에 적용 범위·미적용 선택·요청 복사·분리 집계를 추가했다. 일반 필터와
  처리 범위를 분리하고 추천·항목별 AI 작업 요청에 적용 범위를 사용한다.
- 기존 프로필의 범위 미설정은 전체 선택이 아니다. `unknown`은 미확인으로,
  `info`는 5단계 밖 안내로 분리한다. 결과 형식과 상태 enum은 유지한다.
- SKILL, 작업 프롬프트, 재개·증적·업그레이드 안내를 같은 계약에 맞췄다.
  선택 범위 완료, 전체 완료, 실제 검증과 제출 승인을 구분한다.

## 검토에서 발견해 보완한 항목

| 문제 | 보완·회귀 |
|---|---|
| 과거 소스 검증이 stale이면 범위 설정과 새 snapshot이 서로 막히는 교착 | scope/query/sync는 정상 구조의 소스 변경 stale을 경고로 보존하며 허용. validate의 오류와 status의 전체 진단은 유지 |
| 범위 밖 stale 결과 때문에 선택 범위를 넓혀야 하는 문제 | 범위 밖 결과를 보존한 채 선택 query·sync 가능. 결과/progress 바이트 보존과 경고 확인 |
| 범위 메타데이터 손상으로 전체 status 진단까지 사라짐 | 범위 오류만 별도 표시하고 전체 복구 후보·체크포인트·검증 상태 보존. 선택 실행은 계속 차단 |
| Python이 잘못된 UTC 오프셋 분을 정규화해 화면과 다르게 허용 | 오프셋 시·분 범위 검사와 실제 Python/JavaScript 교차 테스트 추가 |
| 숫자 rank로 높음 이상 대기 항목을 잘못 집계 | 고정 위험도 등급 사용. medium의 rank가 높아도 제외 |
| 추천 설명과 완료 준비 필드 위치가 모호함 | 적용된 in-scope 추천과 status 최상위/nested 필드를 구분해 문구 수정 |

구조가 손상된 snapshot, null binding, 근거 해시 또는 검증 시각 불일치는
비차단 경고로 낮추지 않는다. 소스가 바뀐 과거 근거를 읽을 수 있다는 사실을
현재 검증 완료나 범위 확대 권한으로 해석하지 않는다.

## 자동 검증

정본 테스트 **210개** 통과:

- SAST Python **104개**: toolkit 56, state 39, 사용 안내 렌더러 9.
- 체크리스트 Node **81개**: 5단계 경계, 미설정·손상, 혼합 그룹, 결과 보존,
  요청 복사·추천·필터 독립, Python/JavaScript 분류·집계·시각 검증 일치 포함.
- Architect **24개**, 패키징 **1개**.

배포 사본 Node **81개**도 별도로 통과했다. toolkit sync 후 validate 통과
(배포 템플릿에 실제 입력이 없다는 예상 경고 1건). JavaScript 문법,
정본·배포 사본 일치, 두 매니페스트와 README 버전 일치, diff 공백 검사 통과.

새 동작과 리뷰에서 발견한 결함은 실패를 먼저 재현하고 수정 뒤 재검증했다.
독립 리뷰가 위 경계를 재현했고 보완 후 재검토도 통과했다. 재검토에서는
Python 16개·화면 11개와 식별자·프로젝트·근거·시각·경로 손상 7종에 대한
21개 거부 검사를 별도로 실행했으며 추가 병합 차단 문제를 발견하지 못했다.

## 문서 소비·실제 화면 검증

독립 소비자에게 SKILL과 참조 문서만 제공하고 합성 7등급 상황을 해석하게 했다.
변경 전에는 단일 등급 조회·메모에 의존했고 미확인을 범위 밖에 합쳐 셌다.
변경 후에는 범위 기록·선택 query·재개 절차를 사용하고 대상 3, 범위 밖 3,
미확인 1로 구분했다. 전체 완료 주장과 범위 밖 일괄 보류 변경도 거부했다.
테스트 상황을 이해한 결과이며 실제 고객 프로젝트 처리의 증거는 아니다.

임시 복사본과 합성 항목 7건으로 실제 브라우저에서 확인했다.

- 미설정에서 전체 7건 열람, 미확인 1건·범위 미설정 6건, AI 요청 차단.
- high 적용 후 대상 3건·범위 밖 3건·미확인 1건과 추천 3건 일치.
- 범위 밖 상세·기존 기록 열람 가능, AI 요청 버튼 비활성 및 이유 표시.
- 목록을 low로 필터링해도 high 이상 추천 유지. 미적용 critical 선택과
  필터 초기화가 적용된 high 범위를 바꾸지 않음.
- 실제 복사 내용의 식별자·임계값·명령 확인. 복사 후에도 미적용 표시 유지.
- 980px·390px 너비에서 패널과 페이지 가로 넘침 없음. 선택 상자에서 Tab으로
  사유 입력란 이동과 초점 표시 확인. 수집된 JavaScript 오류 없음.

## 한계와 반영 범위

- 실제 Sparrow 고객 차수의 조치·재검증, LSP 연결 시험, 실제 모바일 기기·
  스크린리더·모든 브라우저 조합은 시험하지 않았다.
- 이 세션에는 호출 가능한 LSP가 없어 범위를 좁힌 소스 탐색과 실행 테스트로
  대체했다. 스킬 기본 형식 검사기는 PyYAML 부재로 실행되지 않았다. 별도 YAML
  파싱으로 두 스킬의 필수 frontmatter를 확인했고 실제 소비 시험을 병행했다.
- 세션 자동 재시작·네트워크 감시 기능은 추가하지 않았다. 저장된 범위를
  수동 재개 때 다시 읽는다. 도구 경계는 임의 에디터·명령을 격리하지 않는다.
- 설치본 업데이트는 별도 작업이다. 저장소 푸시만으로 기존 설치 캐시나 진행
  프로젝트의 복사된 툴킷이 바뀌지 않는다. 원격 반영 상태는 Git 기록을 확인한다.
