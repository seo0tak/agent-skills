# 두 스킬 개선·검증 보고서

2026-09-09 · 작업 브랜치 `codex/resilient-skill-workflows`

이 문서는 1.12.0 / 0.4.0 구현 단계의 범위와 결과를 기록합니다.
이후 커밋·병합·배포 상태는 [HANDOFF.md](../../HANDOFF.md)의 최신 확인 내용을 참고하세요.

## 결론과 범위

합의한 두 단계, **중단 후 수동 재개**와 **승인 범위의 개선 기록**을 구현했습니다.
SAST 작업 트리 버전은 1.12.0, skill-architect는 0.4.0입니다.
최종 검증·사본 동기화 결과는 아래 실행 기록을 기준으로 확인합니다.

자동 재시작·네트워크 감시·무승인 자체 수정·배포는 추가하지 않았습니다.
기존 미커밋 변경을 보존했으며 커밋·push·설치본·실제 프로젝트 업그레이드는
이번 작업에 포함하지 않았습니다.

## 구현한 기능

### SAST 재개와 검증

- 수정 전·후 체크포인트에 대상 파일·현재 판단·임시 진행상태·다음 작업을 저장합니다.
- 검증 직전 소스 스냅샷을 만들고, 실제 통과 근거·시각과 파일 내용을 연결합니다.
  소스·근거가 바뀐 `stale`, 연결 없는 옛 검증 `unbound`를 구분합니다.
- `status`는 읽기 전용입니다. 손상된 진행상태 복구는 미리보기 후 `--apply`에서만
  반영하며 원본을 보존합니다. 기록에 없는 메모·작업은 복구했다고 주장하지 않습니다.
- 고유 임시 파일·원자 교체·협조 잠금으로 도구 작성자 간 충돌을 줄입니다.
- 손상·결과 불일치·오래된 연결 상태를 query/sync에서 소비·게시하기 전에 검사합니다.
  입력 gate는 작업 상태와 분리해 손상 progress 때문에 복구 진입이 막히지 않게 했습니다.

명령은 `skills/sast-remediation/toolkit/tools/README.md`, 실제 재개 절차는
`prompts/07-resume.md`, 검증 연결 순서는 `prompts/03-remediation-wave.md`가 기준입니다.

### 체크리스트 화면

- 추출한 상세 결과 전체를 상태와 같은 저장 항목에 보관합니다. diff 원문도
  재로드·백업·가져오기·재수출 과정에서 보존합니다.
- 브라우저 저장, 화면에만 남은 저장 실패, 정본 반영 대기, 정본 내용 일치를 구분합니다.
  다운로드를 정본 저장이나 실제 검증의 증거로 취급하지 않습니다.
- 잘못된 백업을 전체 검증한 뒤 거부하며, 읽지 못한 저장본은 부팅·후속 저장이
  덮어쓰지 못하게 보호합니다. 그 원문과 현재 화면 작업을 각각 백업할 수 있습니다.
- 가져오기 결과는 실제 적용·동일·더 최신인 현재 값 유지·알 수 없는 ID로 나눕니다.
- 프로젝트·보고서 표시, 비누적 상태 집계, 검증 상태 설명, 상세 결과 구획·코드 영역,
  좁은 화면의 소스 매핑 정보를 정리했습니다.
- 기존 키보드·포커스·모달·페이지네이션 개선을 보존했습니다.

### skill-architect

요청이 있을 때만 프로젝트별 개선 기록을 사용합니다. 단회 감사는 가볍게 유지합니다.

`captured → proposed → evaluated → approved → applied → verified`

후보·대상 해시·평가·실제 사용자 권한의 참조를 연결하고, 후보 변경 시 기존 평가와
승인 참조를 무효화합니다. 적용 후 회귀·버전·복구 가능성을 기록해야 검증 완료로
진행할 수 있습니다. 중단 시에는 체크포인트의 구체적인 다음 행동부터 보여줍니다.

이 도구는 **기록의 정합성**을 검사합니다. 권한 참조의 진위, 실제 파일·테스트 결과는
별도로 확인해야 합니다. 저장된 명령·패치·경로는 실행하지 않으며 모델을 학습시키지 않습니다.
자세한 계약은 `skills/skill-architect/references/improvement-workflow.md`에 있습니다.

## 독립 리뷰와 후속 수정

초기 테스트 성공에 그치지 않고 별도 에이전트가 소비자 시나리오와 실패 경계를 검토했습니다.

- 브라우저: 부팅 중 거부 원본 덮어쓰기, 저장 실패 표시, enum 타입·상속 키 우회,
  오래된 백업 건수 오표시를 실제 함수로 재현하고 수정했습니다.
- 상태·IO: 구조 손상 progress 복구, 잘못된 draftResults 수용, 빈 검증 근거·동일 시각,
  query/sync의 정본 불일치 누락, gate 잠금 누락을 재현하고 수정했습니다.
- 통합: 입력 gate가 손상 progress까지 읽어 복구 전에 막히던 경로를 분리했습니다.
- 문서: 입력 선택·빠른 시작·이월 요약·증적의 검증 신선도 표시·화면 조작 주체를 보완했습니다.
- Architect: 독립 소비자 테스트에서 중단·후보/대상 변경·실패한 회귀·권한 부재·위조된
  참조·명령 문자열·성공 응답 유실 후 재시도를 확인했습니다. 기록 도구의 비실행 경계가 유지됐습니다.
  체크포인트 다음 작업을 우선 표시하도록 추가 개선했습니다.
- 패키징: 실행 중 생성한 잠금이 배포 사본에 섞이던 사례를 테스트로 재현하고 제외했습니다.
  원본 잠금 파일은 삭제하지 않았습니다.

## 검증 실행 기록

독립 리뷰 원문은 작성자의 로컬 검증 자료로 보존되어 있으며 이 저장소에는
포함되지 않습니다. 파일명은 `review-durable-state.md`, `review-browser-renderer.md`,
`review-improvement-forward.md`, `review-guidance-forward.md`입니다.
공유 저장소에서 확인할 수 있는 실행 명령·결과·한계는 아래에 기록합니다.

최종 정본 자동 테스트는 **151개 모두 통과**했습니다. SAST 82개, Architect 24개,
브라우저 44개, 패키징 1개입니다. 배포 사본의 브라우저 44개도 별도로 통과했으며
중복 실행은 151개에 더하지 않았습니다.

상태·IO 독립 재검토는 기존 5건의 해결과 새 차단 결함 없음을 확인했습니다.
gate 단독 복구 시험에서도 입력 미러만 복구하고 손상 progress 원문을 보존했으며,
후속 status/validate는 손상을 계속 보고했습니다. 문서 독립 재검토의 5건도 모두
종결됐습니다. 브라우저의 기존 4개 재현 시나리오는 주 에이전트와 독립 리뷰어가
각각 재실행해 해결을 확인했습니다. 리뷰어는 정본·사본 88/88 통과와 읽지 못한
원문을 백업한 뒤에도 원본·쓰기 보호가 유지됨을 확인했습니다. 종결 재검토에서
새 차단 결함은 보고되지 않았습니다.

프런트매터는 Ruby YAML 파서로 두 SKILL의 실제 YAML, 허용 필드, 이름·설명 길이를 검사했습니다.
시스템·번들 Python에 PyYAML이 없어 공식 quick_validate.py는 실행하지 못했습니다.
대체 검사를 공식 도구 통과로 표시하지 않았고 의존성 설치도 하지 않았습니다.
LSP 도구가 제공되지 않아 소스/참조 검색, Python 구문 검사와 행동 테스트를 사용했습니다.

## 확인하지 않은 범위와 다음 단계

- 실제 브라우저 렌더링·확대·반응형·스크린리더·파일 출처 저장 정책은 미확인입니다.
  로컬 파일 URL 접근이 차단돼 다른 브라우저·localhost로 우회하지 않았습니다.
  VM/DOM 테스트를 실브라우저 검증으로 주장하지 않습니다.
- 프로세스 종료·협조 작성자 충돌은 합성 테스트 범위입니다. 전원 차단·디스크 고장·
  네트워크 파일시스템·클라우드 동기화의 내구성을 보장하지 않습니다.
- 실제 고객 차수, 운영 설정·외부 시스템, 제출 xlsx의 실물 산출물은 이번에 실행하지 않았습니다.
- 원문 답변 입력창에서 아직 “결과 추출”하지 않은 텍스트의 장기 저장은 제공하지 않습니다.
- 반복 모델 압박 테스트 5회나 실제 스킬 발동률 평가는 수행하지 않았습니다.
- 다음 권장 단계는 허용된 브라우저 환경에서 실제 복구·다운로드·390/1024/1440px 화면을
  확인하고, 합성 또는 비식별 프로젝트 1개에서 재개·검증·증적 흐름을 끝까지 실행하는 것입니다.
  그 후 별도 사용자 요청에 따라 커밋·배포·설치본·프로젝트 복사본 업그레이드를 진행합니다.
