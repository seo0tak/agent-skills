# 판정 기준·작업 상태 분리 개선

## 범위와 결과

`sast-remediation` 1.12.4와 `skill-architect` 0.4.3의 정본, 관련 안내와
플러그인 배포 사본을 갱신했다. JSON 필드·enum·schemaVersion 1.0은 유지한다.
고객 소스 수정, 검사 범위의 적절성 판단, 과거 결과의 자동 재분류와 진행
프로젝트 복사본 업데이트는 범위에서 제외했다. 이 문서의 구현 검증 시점에는
커밋·푸시·설치본 갱신 전이었으며, 이후 사용자 승인을 받아 별도 배포 단계로
진행한다. 실제 Git 반영 상태와 설치 버전은 각각 확인해야 한다.

## 반영한 내용

- 규칙 적용 여부 → 현재 영향·안전 조건·미확인 → 조치 필요성 → 실제 작업
  단계의 순서로 판단하고 기존 결과 필드에 구분해 기록한다. 피해가 작거나
  재현되지 않았다는 사실만으로 오탐으로 분류하지 않는다.
- 그룹의 각 항목에서 타입·호출자·설정 등 핵심 조건을 대조한다. 이전 결론의
  근거가 바뀌면 의존하는 판정을 재검토하며, 기술 사실과 정책 승인을 구분한다.
- 판정 가이드와 합성 사례 8개를 추가했다. 정상 바인딩과 원문 SQL 삽입,
  안전 조건 제거, 낮은 영향의 품질 규칙, 예외 승인, 오탐과 예방 변경,
  근거 부족, 더미 이메일, 시프트 규칙의 실제 적용 조건을 다룬다.
- Architect는 이 기준을 판단·상태 처리 흐름이 있는 스킬에만 적용한다.
  일회성 지식 답변에 새 스키마나 상태 저장소를 요구하지 않는다.

## 체크리스트의 재현된 문제와 수정

| 입력·상황 | 이전 동작 | 수정 후 |
|---|---|---|
| 수정 제안, 작업 상태 생략 | 변경 완료로 추론 | 분석 완료 초안 |
| 오탐 + 예방 변경 완료 | 작업 상태가 분석 완료로 축소 | 오탐 / 변경 완료를 독립 보존 |
| “오탐 아님”, 복수·중복 결론 | 부분 문자열·첫 라벨로 결정 가능 | 경고, 기존 기록 유지 |
| 상태만 있거나 적용 내용 없는 변경 완료 | 상세 유실·근거 없는 완료 가능 | 경고, 기존 기록 유지 |

`작업 상태:`는 선택 라벨이다. 없거나 비어 있으면 새 추출 결과만 `analyzed`로
만든다. 기존 유효한 JSON 결과·백업은 일괄 변경하지 않는다. 코드 변경이 없는
운영 조치는 실제 적용 내용이 있으면 기록할 수 있으며 파일·diff를 강제하지 않는다.
내용이 비어 있지 않은지 검사하는 것은 실제 변경이나 판단의 타당성을 입증하지 않는다.

## 검증

- 기본 회귀: SAST Python 83개, Architect Python 24개, 패키징 1개,
  체크리스트 Node 68개 — 정본 기준 총 176개 통과.
- 배포 사본의 체크리스트 68개도 별도로 통과. 정본·사본 및 두 플러그인의
  Claude/Codex 매니페스트·README 버전 일치 확인.
- 새 회귀는 실제 답변 추출·저장·새로고침·백업·내보내기를 실행한다.
  내보낸 결과를 임시 툴킷에서 Python sync·validate·query로 처리해 상태 보존도 확인했다.
- 실제 인앱 브라우저의 합성 데이터에서 오탐/변경 완료 동시 표시,
  부정문 거부, 적용 내용 누락 거부, 상태 없는 수정 제안의 분석 완료 저장,
  새로고침 후 초안 보존을 확인했다. 안내·경고의 기본 화면 표시도 확인했다.
  고객 데이터는 사용하지 않았고 로컬 테스트 서버·탭은 종료했다.
- 툴킷 validate: 오류 0개, 배포 템플릿에 실제 입력이 없다는 예상 경고 1개.
  저장소 안에서 preflight/init 또는 실제 업무 승인 처리를 실행하지 않았다.
- 독립 코드 리뷰에서 발견한 적용 내용 누락 및 가이드 배포 경로 문제를
  수정했다. 두 스킬을 사용한 합성 상황 검토로 판단 분리와 해당없음 처리도 확인했다.

## 한계

LSP가 연결돼 있지 않아 제한된 참조 검색, 실제 구현 읽기, JavaScript 구문 검사와
회귀 테스트로 검증했다. `skill-creator`의 quick_validate는 PyYAML 부재로 실행하지
못했으며, 설치하지 않고 Ruby YAML 파서로 필수 frontmatter를 별도 확인했다.

합성 상황 검토는 실전 차수 전체 실행이나 블라인드 모델 성능 평가가 아니다.
실제 오탐률 개선, 모든 모델의 지침 준수, 모바일·스크린리더 전체 검증,
실제 DB·서비스·외부 정책의 안전성을 확인한 것으로 확대하지 않는다.
브라우저의 수동 단계 선택은 기존의 검토 초안 기능으로 남으며, 정본 검증·승인은
별도 절차다. 스킬이 자율적으로 정책을 바꾸거나 배포하도록 확장하지 않았다.
