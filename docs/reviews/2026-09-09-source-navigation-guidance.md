# 소스 탐색 지침·Sparrow 용어 반영

- 기준: `97daeb7` → sast-remediation 1.12.2 / skill-architect 0.4.2
- 범위: 두 스킬의 지침, SAST 관련 문서·Claude 작업 에이전트, 배포 버전·사본
- 승인: 두 스킬에 검토 내용을 반영하고 푸시하라는 사용자 요청

## 변경 내용

SAST의 탐색 규칙은 `SECURITY_SAST_WORKFLOW.md`에 모으고 SKILL, 초기 분석,
조치, 재개, 테스트 가이드와 프로젝트 지침 예시에서 연결한다. Architect는
자신의 소스 검토 행동과 감사 대상 스킬의 조건부 평가 기준을 구분한다.

- 실제 도구·언어·작업 루트·응답을 확인한 뒤 의미 기반 탐색에는 LSP를 우선한다.
- 파일 목록, 문구·설정값·보고서 구문, 심볼, 구문 구조의 탐색 방법을 구분한다.
  AST 일치나 검색 0건을 전체 참조 또는 안전성의 증거로 보지 않는다.
- 변경 전 참조·동적 연결을 확인하고 편집 후 최신 진단을 확인한다. LSP가 없으면
  범위를 좁힌 검색·실제 소스·타입 검사/컴파일·린트·관련 테스트로 보완한다.
- 재개 후 오래된 색인·참조를 재사용하지 않고, 하위 에이전트의 도구 차이와
  대체 절차의 한계를 명시한다. 확인하지 못한 고위험 변경만 보류한다.
- Sparrow의 보고서 해석과 일반 PDF·스프레드시트 입력 계약을 구분한다.
  다른 검사 도구에 Sparrow 컬럼·위험도 해석을 그대로 적용하지 않는다.

## 호환성과 실행 경계

실행 코드·데이터 형식·상태 전이·JSON 키·enum은 변경하지 않는다.
`report.vendorAttributes`는 유지하고 설명만 수정한다. 내부 `vendor_mode`,
의존성 디렉터리 `vendor`, 원문 컬럼과 예시도 보존한다. 스키마는 설명을
제외한 파싱 결과가 기준 커밋과 동일한지 대조했다. 데이터 이전은 필요 없다.
버전 정책의 문서·형식 무변경 패치에 해당한다.

LSP 설치·외부 소스 전송·사용자/프로젝트의 권한 설정 변경·자동 기동은 추가하지 않는다.
Claude remediator의 배포용 도구 목록에는 읽기 전용 `LSP`만 추가하고 기존 도구를
유지했다. permissionMode나 MCP 서버 설정은 변경하지 않았고 bulk-worker도 그대로다.
설치된 플러그인과 진행 중 프로젝트의 복사본은 이번 작업에서 갱신하지 않는다.

Claude의 도구 허용 목록과 실제 도구 노출은 별개다. 공식 안내는 전경/백그라운드
하위 에이전트에 서로 다른 필터가 적용된다고 설명한다. 따라서 목록만으로 LSP
사용을 보장하지 않고 실제 환경 확인과 메인 세션의 근거 전달/대체 절차를 요구한다.
([Claude 하위 에이전트 도구](https://code.claude.com/docs/en/sub-agents#available-tools),
[LSP 동작](https://code.claude.com/docs/en/tools-reference#lsp-tool-behavior), 2026-09-09 확인)

## 검증

기존 자동 검사의 범위는 상태·정합성·데이터·브라우저 함수 회귀다. 이 성공을
에이전트가 모든 환경에서 새 지침을 따른다는 보장으로 확대하지 않는다.

| 검사 | 결과 |
|---|---|
| SAST Python 회귀 | 83개 통과 |
| Architect Python 회귀 | 24개 통과 |
| 정본 Node 브라우저 함수 회귀 | 52개 통과. 실제 브라우저 시각/E2E 시험 아님 |
| 패키징 회귀 | 1개 통과. 정본 자동 검사 합계 160개 |
| 배포 사본 Node 회귀 | 52개 별도 통과 |
| 툴킷 validate | 오류 없음. 빈 배포 입력 경고 1건 |
| SKILL frontmatter | Ruby YAML 파싱·허용 키·이름·description 형식 검사 통과 |
| 스키마 호환 | `vendorAttributes.description` 외 변경 없음 |
| 배포 일치 | 두 정본·사본 일치, Claude/Codex 버전과 README 일치 |

기본 `quick_validate.py`는 현재 Python에 PyYAML이 없어 실행되지 않았다.
이를 통과한 것으로 기록하지 않으며, 의존성을 설치하지 않고 위 대체 검사를 했다.

### 지침 소비 점검

기준 커밋의 문서를 별도 에이전트가 읽은 대조 점검에서 LSP 선택, 재개 후 색인,
텍스트/AST 용도 구분, 하위 에이전트의 도구 차이에 관한 구체적 절차가 빠져 있음을
확인했다. 기존 문서에도 호출부 확인과 검증 실패 처리 규칙은 있었다.

Architect 수정본은 문서 전용 감사, 사용 가능한 LSP와 오버로드 함수 변경,
재개 후 오래된 참조와 납기 압박, 메인/하위 에이전트의 도구 차이, 새 타입/import
오류의 5개 상황에서 다음 행동과 대상 스킬의 판정을 구분해 설명하는지 점검했다.
5개 모두 필요한 절차를 찾아 설명했다. 승인된 변경 범위와 영향 검증은 별개다.

SAST도 사용 가능한 LSP와 오버로드 함수, 재개 후 오래된 참조와 납기·기존 작업·
동료 의견의 압박, 텍스트/AST 검색, 하위 에이전트의 도구 차이, 새 타입/import
오류의 5개 상황을 별도 소비자가 점검했다. 각 상황에서 해당 지침을 찾아 현재
근거 확인·대체 절차·영향이 불명확한 변경 보류·재검증으로 연결했다.
문서에서 지침을 찾을 수 있다는 결과이며 실제 도구 실행 성공을 뜻하지 않는다.

이 점검은 문서 검색·적용에 대한 제한된 평가다. 새 에이전트 생성 한도로 독립
새 문맥의 반복 실험을 충분히 구성하지 못했으므로, 5회 이상 반복한 행동 벤치마크나
발동률 평가로 보고하지 않는다. 실제 LSP가 노출되지 않아 정의·참조·진단 호출은
실행하지 않았다. 실제 Sparrow 보고서·새 설치 환경에서의 운영 시험도 별도다.

최종 독립 리뷰는 기준 커밋 대비 정본 지침·Claude 에이전트·매니페스트·생성 안내·
이 기록을 검토하고, 사본 일치와 스키마 설명 외 무변경을 별도로 확인했다.
수정이 필요한 Critical/Important/Minor 발견은 없었고 병합 가능으로 판정했다.
리뷰어가 자동 검사 전체나 실제 LSP 실행을 별도로 반복한 것은 아니다.
