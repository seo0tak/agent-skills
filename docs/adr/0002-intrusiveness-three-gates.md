# 어댑터 실행은 침습도 세 겹으로 판정한다

security-assessment가 스캐너 어댑터를 직접 실행할지, 운영자에게 명령을 지시할지는
침습도(intrusiveness)로 판정한다: ① 어댑터의 침습도가 스코프의 침습도 상한을
넘으면 금지, ② `active-nondestructive` 이하이고 사용자가 직접 실행을 명시하면
스킬이 실행, ③ 그 외(intrusive이거나 사용자 미명시)는 운영자에게 명령을
지시한다. intrusive 어댑터는 스코프 건별 인가 + 운영자 실행만 허용한다.

대상 타입(repo/web/infra)으로 가르지 않고 침습도로 가르는 이유는, "로컬이니까
안전"이 거친 기준이기 때문이다 — 로컬 대상에도 활성·간섭 스캔이 있을 수 있고,
원격 대상에도 순수 수동(passive) 점검이 있다. 침습도는 스코프에 이미 있는 축이라
게이트·어댑터·실행 판정이 하나의 축으로 일관되게 움직인다.

## Considered Options

- 대상 타입으로 가름(repo=직접, web/infra=운영자) — 단순하지만 로컬 활성 스캔을
  사용자 명시 없이 돌리게 되고, 타입과 위험이 일치하지 않는다.
- 항상 운영자 지시, 직접 실행 없음 — 가장 안전하고 감사에 유리하나, 비파괴 로컬
  스캔마저 수동이라 스킬의 값이 떨어진다.

## Consequences

- 비파괴 로컬 코드 스캔도 사용자가 "직접 실행"을 명시해야 스킬이 돌린다. 명시가
  없으면 명령만 지시한다 — 의도적인 마찰이다.
- intrusiveness가 게이트(스코프 상한)·어댑터·실행 판정 셋에 모두 쓰이므로, 이
  enum을 바꾸면 세 곳을 함께 본다.
