# 웹 스캔은 스캐너가 범위를 지킬 때만 돌리고, URL 검출은 정규화한 지문으로 묶는다

웹(DAST) 어댑터는 실제 요청을 보내므로, 제외 자산과 대상 밖 호스트를 결과에서 빼는 것으로는
범위를 지킬 수 없다. 그래서 어댑터 선언에 제외 자산과 대상 범위를 스캐너 옵션으로 넘기는
방법을 적게 하고, 그 방법이 없는 어댑터는 대상 안에 제외 자산이 있으면 실행도 들여오기도
거부한다. 결과에서 빼는 필터는 그대로 둔다(이중 방어). 직접 실행은 ADR 0002를 따르되, 웹
대상은 실행 직전에 대상 URL·요청 속도 상한·예상 시간·제외 목록을 보여 주고 그 실행에 대한
사용자 확인을 받으며, 점검 기간 끝을 넘지 않는 시간 상한을 둔다. M3는 로그인 없는 표면만
다루고, 인증이 필요한 스캔은 운영자가 돌려 `ingest`로 들여온다. URL 검출의 지문은 메서드·
호스트·정규화한 경로(숫자·식별자 세그먼트는 자리표시자)·영향받는 파라미터 이름으로 만들고,
쿼리 값·세션 토큰·증거 문자열은 넣지 않는다.

## Considered Options

- 제외 자산이 있으면 웹 스캔은 항상 운영자 — 안전하지만 범위를 지킬 수 있는 도구까지 손으로
  돌려야 한다.
- 결과 필터만 유지하고 문서로 경고 — 가장 단순하지만 범위 밖 트래픽을 막지 못한다.
- 웹 대상은 침습도와 무관하게 항상 운영자 — ADR 0002의 "타입이 아니라 침습도" 원칙과 어긋나고
  비파괴 스테이징 스캔도 수동이 된다.
- 인증 스캔을 환경 변수 참조로 지원 — 자격증명 보관·전달·증적 노출 설계가 따로 필요해 미뤘다.
- 스캐너 규칙 ID + 쿼리를 뺀 URL을 지문으로 — 단순하지만 경로에 ID가 든 엔드포인트가 건마다
  갈라지고 스캐너 간 묶음이 안 된다.

## Consequences

- 어댑터 스키마에 범위 제어 선언(제외·대상 범위를 넘기는 인자 템플릿)이 생긴다. 이 선언이
  없는 웹 어댑터는 제외 자산이 없는 대상에서만 쓸 수 있다.
- 실행 판정이 "침습도 세 겹 + 웹 대상의 실행 직전 확인"이 된다. 확인은 실행 한 번에 대한
  것이며 다음 실행에 넘어가지 않는다.
- 같은 결함을 다른 쿼리 값으로 다시 찾아도 같은 검출로 묶이고, 차수 간 해소 판단이 쿼리 값
  변화에 흔들리지 않는다. 대신 같은 경로의 서로 다른 파라미터 결함은 파라미터 이름으로 갈린다.
- 크롤링 범위는 실행마다 달라질 수 있어, 웹 검출의 "다음 차수에 안 보임"을 해소로 볼지는
  M3 구현 전에 따로 정한다(같은 어댑터·같은 대상 재실행 조건만으로 충분한지).
