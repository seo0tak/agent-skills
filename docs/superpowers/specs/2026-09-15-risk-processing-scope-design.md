# 위험도 기반 처리 범위 설계

사용자 승인: 전체 보고서를 보존하고 선택한 위험도만 상세 분석·조치·검증한다.
추천 작업, AI 실행, 재개, 완료 집계에 같은 기준을 적용하고 구현 후 푸시한다.
설치본 업데이트와 고객 프로젝트의 소스·복사된 툴킷 변경은 포함하지 않는다.

## 처리 계약

- 선택지는 `critical`(매우위험만), `very-high`(위험 이상), `high`(높음 이상),
  `medium`(보통 이상), `low`(전체 5단계)다. rank 숫자 대신 이 순서로 판정한다.
- `unknown`·등급 누락은 별도 미확인이다. `info`는 5단계 밖 안내 등급이므로
  범위 밖에 보존한다. 미확인을 낮은 위험도로 간주하지 않는다.
- 입력 게이트와 전체 목록 등록·건수 대조는 모든 항목에 수행한다. 범위는
  상세 분석과 조치 대상을 좁힐 뿐 검사 범위를 다시 정의하거나 위험을 수용하지 않는다.
- 범위 밖 항목의 결론·단계·결과·검증 근거를 범위 설정 때문에 바꾸지 않는다.
  관련 코드는 선택한 변경의 영향·회귀 검증을 위해 확인할 수 있다. 혼합 그룹은
  항목별로 대상 여부를 나누며 공통 수정의 부수 효과를 자동 완료로 올리지 않는다.

## 정본과 호환

`data/project-profile.json`에 선택 필드 `processingScope`를 추가한다.

```json
{
  "workspaceId": "sample-workspace",
  "reportId": "sample-report",
  "minRisk": "high",
  "updatedAt": "2026-09-15T00:00:00Z",
  "updatedBy": "user",
  "reason": "이번 차수는 높음 이상 처리"
}
```

현재 profile의 workspaceId와 report.id에 일치해야 하며 미초기화·빈 식별자,
잘못된 등급·시각·기록자·사유는 거부한다. 선택 기록은 사용자 승인 참조이며
파일만으로 작업·배포 권한을 만들어내지 않는다. 차수가 바뀌면 자동 이월하지 않는다.
필드가 없는 기존 자료는 읽을 수 있지만 `미설정`이다. 상세 실행 전에 사용자
범위를 기록해야 하며 전체로 자동 확대하지 않는다. 기존 결과 형식과 상태 enum,
schemaVersion `1.0`은 유지한다.

## 명령과 실행 경계

```text
python3 tools/sast_toolkit.py scope
python3 tools/sast_toolkit.py scope --min-risk high --set-by user --reason "이번 차수는 높음 이상 처리"
python3 tools/sast_toolkit.py query --scope in-scope --group WG-001
python3 tools/sast_toolkit.py query --scope out-of-scope
python3 tools/sast_toolkit.py query --scope unknown
```

- `scope`만 쓰면 읽기 전용 현황이다. 설정 명령은 입력 게이트 READY와 현재
  작업공간·차수, 인자 유효성을 확인한 뒤 기존 쓰기 잠금·원자 저장으로 profile을
  갱신하고 sync한다. 결과·progress·입력 원본을 수정하지 않는다.
- query는 전체 조회가 기본(기존 감사·복구 조회 호환)이며 대상 조회에는
  `--scope in-scope`를 명시한다. 미설정·손상된 범위에서 대상 조회는 실패한다.
  선택 범위는 기존 ID·그룹·위험도 필터와 교집합이다.
- before-edit checkpoint, snapshot, seal-verification은 항목의 범위 포함을
  확인한다. after-edit checkpoint와 복구·동기화는 이미 생긴 작업을 보존하는
  경로이므로 범위 변경으로 막지 않는다. 이 허용은 추가 수정 권한이 아니다.
- status는 전체 복구 후보를 보존하고 선택 범위 후보·범위 현황을 함께 제공한다.
  범위 메타데이터만 손상됐으면 범위 오류를 명시하고 선택 실행은 차단하되,
  전체 체크포인트·검증 상태·복구 후보를 계속 반환한다.
  이 경계는 제공된 도구 경로의 방어이며 에디터·임의 명령을 격리하는 보안 장벽은 아니다.
- 구조·식별자·검증 근거 연결이 정상인 과거 기록의 소스가 바뀌었으면 범위
  설정·조회·sync는 경고와 함께 가능하다. 그렇지 않으면 미설정 범위와 재검증
  사이에 교착이 생긴다. 전체 validate의 stale 오류와 status 진단은 유지하며,
  범위 밖 stale를 없애려고 처리 범위를 넓히지 않는다.

## 화면

기존 `위험도 필터`와 별도의 처리 범위 패널을 둔다. 적용된 범위·설정 시각과
선택지를 표시하고 `범위 적용 요청 복사`로 AI에게 현재 작업공간·차수와 선택값을
전달한다. HTML은 파일 정본을 직접 저장할 수 없으므로 선택·복사는 적용이 아니다.
미적용 선택을 명확히 표시하고 새로고침하면 정본을 다시 읽는다. localStorage와
기존 백업의 진행 상태가 범위 정본을 덮어쓰지 않는다.

추천 작업과 항목별 AI 작업 요청은 적용된 범위의 항목에만 제공한다. 미설정·잘못된
범위에는 작업 요청을 제공하지 않는다. 목록 조회와 기존 결과 열람은 범위 밖도 가능하다.
필터 초기화는 처리 범위를 변경하지 않는다.

전체·대상·범위 밖·미확인 수와 대상의 검증 완료/남은 수를 분리한다. 대상 0건을
100% 완료라고 표시하지 않는다. 브라우저는 초안이 섞일 수 있으므로 단계 집계이며
현재 소스의 검증 신선도·제출 승인까지 증명하지 않는다. 보고·증적은 선택 범위만
완료한 것을 전체 완료로 쓰지 않으며 범위 밖과 미확인도 전체 목록에 남긴다.

## 검증과 배포

5단계 경계, info/unknown, 미설정/손상, 설정 저장·재개, 혼합 그룹, 범위 확대·축소,
표시 필터 초기화, 기존 결과·백업 보존, CLI/화면 분류 일치를 합성 입력으로 검증한다.
실제 브라우저에서 패널·미적용 표시·요청 복사·추천·키보드·작은 화면을 확인한다.
SAST 기능 버전은 1.13.0, Architect는 기능 변화가 없으므로 0.4.3을 유지한다.
배포 사본 동기화와 기존 전체 회귀를 통과한 뒤 기존 main에 통합·푸시한다.
