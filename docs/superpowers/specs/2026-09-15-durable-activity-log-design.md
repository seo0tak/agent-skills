# SAST 누적 작업 이력 설계

## 승인과 범위

2026-09-15 사용자 승인: 작업 시작·실패·오류·중단·재개, 중요한 변경의 누적 보존,
체크리스트 HTML의 전체/항목별 조회를 구현하고 푸시한다. 기존 결과·진행·재개
JSON은 유지한다. 고객 프로젝트, 설치된 플러그인, 원격 실행 환경은 변경하지 않는다.

## 구조

- Python 표준 라이브러리와 기존 정적 HTML/JS만 사용한다.
- `data/activity/` 아래 월별 디렉터리에 이벤트마다 독립 JSON 파일을 안전하게
  생성한다. 기존 이벤트를 덮어쓰거나 자동 삭제하지 않는다. 날짜별 분리는 보관이지 삭제가 아니다.
- `data/activity.js`는 화면용 생성물이다. 누적 이벤트가 정본이며 화면 필터,
  처리 범위, 결과 재읽기와 무관하게 보존한다. 이전 차수 기록도 보존하고 차수 출처를 표시한다.
- 브라우저 상태 변경 이력은 기존 상태+초안 저장 봉투의 선택 필드 `activityEvents`에
  함께 저장·백업한다. 파일 로그와 브라우저 초안은 구분한다. 파일 반영은 명시적 가져오기다.
- 결과·정책·진행 파일의 직접 변경은 sync/reconcile 시 이전 관측값과 대조하여
  변경 발견으로 남긴다. 실제 수정 주체·시각을 알 수 없으면 추측하지 않는다.

## 이벤트 계약

이벤트 공통 필드: `schemaVersion: "1.0"`, `eventId`, `recordedAt`,
`workspaceId`(문자열 또는 null), `reportId`(문자열 또는 null), `operationId`,
`attemptId`, `kind`, `action`, `outcome`, `source`, `actor`, `itemIds`,
`summary`, `before`, `after`, `evidence`, `important`.

- `kind`: `started`, `finished`, `changed`, `observation`.
- `outcome`: `running`, `succeeded`, `failed`, `blocked`, `stopped`, `info`.
- `source`: `toolkit`, `agent`, `browser`, `external`.
- `before`, `after`: 작은 JSON 객체. 상태·결론·범위·해시 중심이며 전체 소스/대형 결과를 복제하지 않는다.
- `evidence`: 문자열 배열. 실행할 명령이 아니라 근거 참조다.
- `operationId`는 논리 작업, `attemptId`는 한 번의 시도다. 같은 이벤트 재수신은
  중복 생성하지 않고, 같은 ID의 다른 내용은 거부한다. 재시도는 새 attemptId를 사용한다.
  같은 작업 ID에는 작업공간·차수·작업 종류·출처·대상 항목이 일치해야 한다.
  담당자 변경은 가능하다. 내부 정본 관측은 작업의 근거로 연결하되 일반 메모나
  브라우저 입력으로 위조할 수 없도록 예약 이름과 관측 출처를 검사한다.
- 시작 뒤 종료가 없으면 projection에서 `unfinished`로 집계한다. 실행 중인지
  비정상 종료인지 단정하지 않는다. 읽기 전용 status는 종료 이벤트를 만들어내지 않는다.
- 정상 명령 종료와 취약점 검증 완료는 다른 개념이다. 로그에서 workflowStatus를 승격하지 않는다.

화면용 봉투: `window.SAST_TOOLKIT_DATA.activity`에
`{schemaVersion: "1.0", generatedAt, events, warnings}`를 저장한다.
빈 배포본은 events/warnings가 빈 배열이며 실제 작업 기록은 포함하지 않는다.

## 실패와 재개

변경 명령은 시작 기록 성공 뒤 실행하고 실제 결과를 종료 기록으로 남긴다.
관찰 가능한 예외·사용자 중단은 기록하고 다시 실패를 알린다. 강제 종료·전원 상실은
종료 기록을 보장할 수 없으므로 미종료 시도와 현재 파일을 대조한다.
로그 저장 자체가 실패하면 후속 변경을 시작하지 않으며, 변경 후 실패는 반영 여부
확인 필요로 알린다. 소스·JSON·이력 전체가 단일 트랜잭션이라는 보장은 하지 않는다.
재개 도구는 미종료 시도와 기록 불일치를 반환한다. 관측 없는 원인·시각·과거 이력을 생성하지 않는다.

## 최소 CLI

`tools/sast_activity.py`의 `start`, `finish`, `note`, `query`, `status`,
`reconcile`, `import-browser`로 작업과 예외를 명시적으로 기록·조회한다.
start는 action/summary/actor와 선택 항목·operation/attempt ID를 받고 ID를 반환한다.
finish는 attempt ID와 실제 outcome/summary를 받는다. query/status는 읽기 전용이다.
기존 toolkit/state의 변경 명령도 공통 기록기를 사용한다. 배포용 미초기화
툴킷에는 실제 로그를 만들지 않는다. 자동 기록은 초기화된 프로젝트 또는 이미
명시적으로 기록을 시작한 툴킷에서 수행하며 그 전의 오류는 실행 출력으로 확인한다.
query/status/복구 미리보기는
읽기 전용을 유지한다. 재개는 미종료 작업을 대조하고 실제 조치 후 명시적으로 종료한다.

## 화면

전체 작업 로그 패널과 항목별 상세 이력을 제공한다. 최신 기록 시각, 종료 미확인,
실패·차단·중단 건수를 보여준다. 검색, 날짜, 오류/중요/미종료/출처 필터를
검출 목록 필터와 독립적으로 적용한다. 목록은 페이지당 50개와 높이 제한 내부
스크롤, 상세 펼침을 사용한다. 항목 이력은 해당 ID 관련 이벤트만 보인다.
새로 불러온 시각과 생성 시각을 표시하고 실시간 감시로 오해하지 않도록 한다.
출처가 다른 이벤트와 브라우저 임시 기록은 구분하며 로그 입력은 textContent로 렌더링한다.

## 보안·보존·호환

기본값으로 비밀 키·토큰 등의 명시적 값은 마스킹하고 출력 크기를 제한한다.
마스킹은 모든 민감정보 탐지를 보장하지 않는다. 전체 소스·환경변수·원시 출력 수집은 하지 않는다.
심링크·경로 탈출·중복 ID 충돌·손상 기록을 검증하며 손상 원본을 자동 삭제하지 않는다.
과거 데이터는 도입 시점 기준 상태로만 기록한다. 로그 누락을 근거 없는 과거 이벤트로 메우지 않는다.
기존 schemaVersion과 workflow/conclusion enum은 유지한다. 스킬은 1.14.0으로 올리고
skill-architect 0.4.3은 유지한다. 배포 사본은 sync 스크립트로만 생성한다.
로컬 보존은 디스크 손실·변조 방지·외부 백업·자동 재접속을 보장하지 않는다.

## 검증

시작/종료/실패, 강제 중단 후 미종료 검출, 두 번 변경한 이력 보존, 중복 시도와
충돌, 저장 실패 전 실행 차단, 직접 수정 발견, 민감 값 처리, 다른 차수·손상 입력,
브라우저 저장·백업·복원, 필터 독립성·페이지 제한·키보드·좁은 화면을 검사한다.
기존 전체 회귀와 정본/배포본 일치·버전 검사를 실행한다. 실제 고객 차수와 다른 PC는 미검증으로 남긴다.
