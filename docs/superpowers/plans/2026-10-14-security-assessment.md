# 계획 — security-assessment 스킬 (인가 기반 보안 점검 오케스트레이터)

작성 2026-10-14. 상태: **계획 단계**(구현 미착수). 설계 상세는
`docs/superpowers/specs/2026-10-14-security-assessment-design.md`.

## 목표

SAST 결과를 *조치*하는 기존 sast-remediation과 달리, 보안 취약점을 직접
*검사*하는 스킬. Sparrow 같은 정적분석에 더해 의존성·시크릿·웹/API·인프라
점검을 **인가 범위 안에서** 수행하고, 결과를 소스와 대조해 오탐을 거른 뒤
증적으로 정리한다. 확인된 코드 레벨 결함은 SARIF로 sast-remediation에
넘긴다.

핵심 성격: **인가된(authorized) 점검의 오케스트레이터**다. 검증된 오픈소스
스캐너를 조율하고, 침습적 단계는 인가 문서와 스코프 안에서만, 익스플로잇
작성이 아니라 탐지의 **확인·재현 절차**로 다룬다.

## 확정된 결정 (사용자)

- 점검 대상: 소스/저장소(SAST·SCA·시크릿) + 웹/API(DAST·인가된 모의해킹)
  + 인프라/컴플라이언스(IaC·설정) — 전 범위.
- 실행: **혼합** — 기본은 운영자에게 명령을 지시, 사용자가 명시하면 비파괴
  스캔만 스킬이 직접 실행(sast-remediation의 연속 실행 모드와 같은 방식).
- 구조: **별도 스킬** + SARIF 다리로 sast-remediation에 핸드오프.

## 비목표 (하지 않는 것)

- 임의 대상 공격 코드·익스플로잇·페이로드 생성. 대량 타겟팅, 자격증명 수집,
  제3자 서비스 침해, 탐지 회피.
- 인가 범위 밖 대상 점검. 스코프에 없는 호스트/저장소/URL은 게이트가 거부.
- 바퀴 재발명 — 스캐너를 새로 만들지 않고 기성 도구를 래핑.

## 재사용 (sast-remediation에서)

게이트 2단 구조, 파일 상태 저장소, `validate` 기계 강제, 오탐/판정 분리,
증적 워크북, **SARIF 수집 경로**(기존 01-initialize에 이미 있음), 연속 실행
모드, 결정 로그.

## 마일스톤 (tracer-bullet, 각 단계 검증 통과 후 다음)

- **M0 — 인가 게이트 + 뼈대.** 스코프 파일(허용 대상·제외 자산·기간·소유자
  동의 기록·침습도 수준), 기계 점검 + 의미 확인, `validate`. READY 전에는
  어떤 스캔도 안 돈다. 범위 바뀌면 승인 자동 무효. 이 단계만으로도
  "아무것도 실행하지 않는 안전한 스킬"이 성립해야 한다.
- **M1 — 소스 측 오케스트레이션.** SAST(Semgrep/gosec/Bandit), SCA(OSV/
  Trivy/grype), 시크릿(gitleaks) 어댑터. 출력 SARIF 정규화 → 기존 수집 경로.
  도구 미설치 환경은 운영자 지시로 폴백.
- **M2 — 판정·증적·다리.** 소스 대조, confirmed/suspected/false-positive
  판정(이유 필수), CVSS·영향 자산·재현·조치 가이드 증적, SARIF 다리로
  sast-remediation 핸드오프.
- **M3 — 웹/API.** DAST 어댑터(ZAP baseline, nuclei 비파괴 프로파일).
  인가 게이트 강화: 침습적 테스트는 건별 인가, 비파괴 기본값. 수동 확인은
  운영자 실행. 착수 전 설계 점검 결정(ADR 0003): 스캐너가 범위를 지킬 때만
  실행(어댑터 범위 제어 선언), 웹 직접 실행은 실행 직전 확인 + 기간 내 시간 상한,
  비인증만, URL 지문은 메서드·호스트·정규화 경로·파라미터 이름, 요청 상한은 스코프의
  웹 대상(의미 필드)·어댑터가 전달 방법 선언, 웹 해소는 같은 어댑터·대상 재실행 +
  커버리지에 정규화 경로가 있을 때만, 컨테이너는 `{output_dir}`·`{output_name}` 자리표시.
- **M4 — 인프라/컴플라이언스.** IaC·설정(Checkov 등), 기준(CIS 등) 대조. 착수 전 설계 점검
  결정(ADR 0004): IaC + 클라우드 설정(읽기 전용, Prowler 등)까지, 네트워크·호스트 스캔은 제외.
  대상 `aws:<계정>` + 리전 목록 + 자격증명 참조(프로파일·역할 이름, 읽기 전용 확인, 비밀값 저장
  안 함). 계정·리전 제외는 스캐너가, 리소스 제외는 결과 필터. 지문은 리소스 식별자, 묶음은 스캐너
  출력의 통제 항목(매핑표 없음, 없으면 점검 ID). 기준별 통과·실패·수동 건수를 실행 기록·표지에.
  클라우드 해소는 같은 계정·리전·점검 항목 재확인. confirmed IaC는 sast-remediation으로 넘김.
- **M5 — 방법론 체크리스트.** OWASP WSTG / PTES 단계 체크리스트, 탐지
  재현·증적 수집. 위험 단계는 도구가 자동 발사하지 않고 운영자에게 지시.

## 안전 가드레일 (기계 강제 — 문서 규칙 아님)

- 인가 게이트 비우회: 스코프에 없는 대상은 `validate`/실행이 거부.
- 침습도 수준(passive / active-nondestructive / intrusive)별 허용 작업 분리.
  intrusive는 스코프에 명시적 인가 + 운영자 실행만.
- 비파괴 기본값. 스킬 직접 실행은 passive·active-nondestructive로 한정.
- 대상 허용목록 + 제외 자산 denylist를 매 실행 재대조.

## 확정된 결정 (2026-10-14, M0 착수 전 좁힘)

1. **스킬 이름: `security-assessment`.**
2. **동의 기록: 구조화 필드 + 참조.** 인가자·역할·일자 + 티켓/문서 URL.
   `validate`가 존재·형식을 기계 검사한다.
3. **대상 지정: 타입 명시 목록.** 각 대상 `{type: repo|web|infra, value, notes}`.
   게이트가 타입별로 침습도·접근성을 다르게 검사한다.
4. **테스트 대상: 합성 픽스처 + 저장소 밖 임시 사본.** 단위 테스트는 커밋한
   최소 픽스처(`examples/`), 실제 스캐너 구동은 저장소 밖 임시 사본(의도적 취약
   프로젝트)에서. 실제 스캔 산출물은 배포물에 섞지 않는다(CLAUDE.md 원칙).
